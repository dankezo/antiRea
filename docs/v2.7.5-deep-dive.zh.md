# antiRea v2.7.5 深入解析

> 2.7.3 在自己的门槛上排除的房间守卫，补上所缺的那条腿后重建，外加四次邻居解剖产出的证据层。下文一切都是种子模拟或确定性一致性之上的实验室记录；没有任何数字是真实流量测量。

## 第 1 部分 - 本次发布内容

五个新模块，全部是新增、全部仅具咨询性（凡是涉及房间或身份的输出都带 `enforcement: "none"`）。默认路径没有任何变化：没有既有模块导入新模块，758 个既有测试全部不加修改地通过。

- `createRoomGuard`，组合房间压力守卫，pressure v2（RECOMB-06）。
- `createConfigProvenance` / `configProvenanceHash` / `canonicalSerializeConfig`，CS-02，配置来源 pin。
- `classifyWebBotAuthVerdict` / `classifyHostVerificationFact`，BS-01，verified-neutral 验证事实。
- `issueStepUpProof` / `createStepUpProofVerifier`，CAP-01，一次性 step-up proof 代币。
- `evidentiaryRoleOf` / `auditEvidencePack` / `decorateSignalResult`，KT-01，证据角色。

测试套件：793 个测试（791 通过，0 失败，2 个既有 RSA-PSS 跳过），高于 2.7.4 的 758 个，新增 35 个，既有期望零修改。新测试固定的内容包括：一个直接取自实验室探针结果文件的 CS-02 摘要、全部 17 个已发布失败原因的 BS-01 映射、CAP-01 的检查顺序与 nonce 副作用规则、KT-01 的审计包，以及房间守卫在手工构造流上的四条路径。

## 第 2 部分 - 房间守卫，以及它为何需要一次新注册

2.7.3 的变更日志记录了这次排除：一个由加入速度、新账户集中度和加入后不活动组成的冻结组合，通过了误报门和四道机器人门中的三道，却完全漏掉了占座格，pressure 在任何 tick 上都没有变高，因为占座攻击的是随时间持续的占用，而该组合没有占用腿。本项目的规则是：失败的门不能在同一注册内、看过数字之后靠补上缺失的腿来修复。

RECOMB-06 就是那次合法的修复：一次新注册（种子族 20296xxx，与原来的 20286xxx 不相交），预先声明占用腿，其估计量和两条持续规则逐字取自已发布的 `createSeatOccupancySignal`（CAND-273-1/273-2）；并且有一处门的变更在任何数字出现之前就已声明：占座门是 900 秒，而不是草图里的 600 秒，因为这一统计量的物理下限约为 660-720 秒的填座加持续，CAND-273-1 pin 早已测得这一事实。结果文件仍然以描述方式记录相对 600 秒的第一个高 tick：690 秒并不满足它，文件也如实这样写。

## 第 3 部分 - RECOMB-06 记录

种子模拟，30 秒评估 tick x 7 天（每格 20,161 个 tick），原来的合法背景加一个新格。Pressure v2 = 原三条路径或占用腿。

- 误报：pressure 在五个合法格中从未变高，包括稳定影院、50 名既有账户的突袭、60 名用户的定时场次、黄金时段 karaoke，以及 KARAOKE-SILENT（60% 在座会话，无论新旧，都不发出任何活动，这是占用腿最危险的零假设）。合法占用峰值为 0.02-0.10，而 DRIP 阈值为 0.34。
- FLOOD（10 秒内 200 个新账户）：在 +60 秒变高（门为 120 秒），经由原路径。
- DRIP（一小时内每 30-60 秒一个新账户）：在 +1,950 秒变高（门为 45 分钟），经由原路径；占用腿稍后触发（+2,790 秒 FAST / +5,070 秒 DRIP），为描述性记录。
- CHURN（40 个新账户以 5 秒驻留循环）：在 +30 秒变高（门为 15 分钟）。
- SQUAT（30 个新账户在 120 秒内占据全部 karaoke 座位，沉默，保持 1 小时）：在 +690 秒变高（门为 900 秒），仅经由占用 FAST 规则；原三条路径在每个 tick 上都保持沉默，在新种子上复现了 2.7.3 的诊断。
- SQUAT-DRIP（30 个新账户缓慢入座，间隔约 450 秒）：占用 DRIP 规则在最后一个机器人入座前 5,100 秒就已标记（门：至少 1,800 秒预警）。

在注册和模块头中公开声明：漏洞 A1。占座者只要发出哪怕 1-2 个活动事件，就离开了占用腿的零活动定义，而速率路径也看不到缓慢的沉默少数。A1 需要一个关于活动质量的候选；本发布不假装关闭它，并且有一个单元测试固定这条逃逸路径，以免它被遗忘。

## 第 4 部分 - 已发布模块的契约

每个房间一个实例；宿主喂入 `join` / `leave` / `activity` 事件（已知时带 `accountCreatedTs`），读取 `evaluate()`。求值精确复现实验室的 tick 语义：窗口为 (t-W, t]，新近性是加入前不足 24 小时的创建（或首次见到），速度基线是 [t-24h, t-10min] 上每分钟加入数并以 0.5 为下限，占用规则是已发布的 profile（FAST 0.50 / 600 秒，DRIP 0.34 / 3,600 秒）。结果将历史与状态分开：`flagged` / `firstFlagTs` 记录 pressure 曾经变高；`pressureHighNow` 与 `recommendStepUpForNewJoins` 描述最新 tick；每条路径的首次触发时间和当前分量值会报告给宿主的仪表板。没有任何身份级输出，也没有点名成员的 API，后果面恰好就是"pressure 为高时对新加入者 step-up"，这正是 agent 指南经由 `createVerificationGrace` 接入的模式。

## 第 5 部分 - 证据层（CS-02、BS-01、CAP-01、KT-01）

这四个模块出自邻居解剖线（CrowdSec、bot-signal、Cap、Kitsune）：每个邻居都从其自身来源阅读，每个可转移的机制都被注册为候选，每个候选在任何构建之前都在实验室运行了一次冻结的 Step 0。四个 Step 0 都在 2026-11-09 通过；已发布的移植版由单元测试保持与实验室产物的对应，而不是凭相似度。

- **CS-02 ProvenancePin。** 一个信号的裁决取决于它的有效配置；CS-02 把它固定下来：对 `{ kind, version, options }` 的规范序列化做 SHA-256，其中 options 是调用方的值在工厂声明的默认值下解析的结果（未声明的字段永远不会进入）。实验室探针覆盖 2.7.4 已发布 7 个 kind 的 43 个声明选项：跨进程确定性 100%，默认等价性 100%，突变敏感性 100%，0 碰撞，每个 pin 约 0.005 ms，而门为 1 ms。发布实现精确复现了探针的 seat-occupancy 摘要（固定为测试向量），`room-guard` 从本版起加入被哈希的 kind。
- **BS-01 VerifiedNeutral。** 身份验证在任何一个方向上都不是怀疑。冻结表覆盖已发布 Web Bot Auth 结果空间（从源码机械提取的 17 个失败原因，加 FCrDNS 和已发布范围通道，共 26 行），给 verified、no-claim 和每一行 unverified 分配 delta 0，只给恰好两行 spoof 分配 "EVIDENCE"：一个结论性的密码学签名失败（唯一的结论性 `invalid_signature` 细节）和一个 FCrDNS 矛盾。replay 裁决以侧事件形式出现，而不是身份事实。分类器把任何未知原因或未来的细节字符串默认归为 unverified，这样宿主就永远不必自己以细节字符串为依据执行强制。事实可选择携带产生它的验证器配置的 CS-02 哈希。
- **CAP-01 StepUpProofShape。** 一个 Ed25519 代币（三段 base64url），绑定一个身份、它所回答的那次 step-up 的配置的 CS-02 哈希、宿主挑战配置的哈希、一个一次性 nonce，以及上限 3,600 秒、带 60 秒偏差容忍的寿命。验证顺序是冻结的（结构、密钥、签名、声明、时间、绑定、replay），并且构建时必须提供的 consume 钩子恰好在每个到达 replay 步骤的代币上触发一次，从不提前；实验室一致性运行 19/19 精确，钩子在整个套件中触发 4 次，单元测试会对发布的移植版重跑这条规则。
- **KT-01 EvidentiaryRoles。** 每个通道在一条毕业规则下获得一个角色：只有凭借自身通过的门才是 CONVICTING，否则是 CORROBORATING。七个已发布信号是 CONVICTING；`room-guard` 经由 RECOMB-06 在同一规则下加入它们。BS-01 事实是唯一有条件的行（spoofed 定罪，其他一切只作佐证）。`auditEvidencePack` 让后果变得机械：未知通道或误报的角色是无效的，而一个包若没有任何已触发的 CONVICTING 条目就没有资格，无论多少个佐证条目触发。层级重述（观察 / step-up / 以 500 为下限的软降级 / 对推断证据禁止第 3 层）以数据形式发布。

## 第 6 部分 - 本发布不声称的内容

- 房间守卫的每一个数字都是种子模拟（内部有效性），不是真实流量性能；证据层的数字是对冻结表的确定性一致性，不是实地测量。
- pin 转换（C27+C35 从咨询走向分层后果）不在本发布中。它仍然在 2026-11-16 的农场门（对两周农场数据的 CUSUM 拟合加留出验证）和一个生产分层分配机制之后；这里发布的证据层是它的地基，而不是它的启动按钮。
- 五个解剖候选尚未运行它们的 Step 0（CS-01、CS-03、AN-01、AN-02、AN-03），它们不以任何形式出现在本发布中。
- 漏洞 A1（第 3 部分）是开放的。只发出最少聊天的占座者按定义逃逸占用腿。
