# antiRea v2.7.0 深入解析

发布主题：为证据层打造一个数学核心，外加一波堵住其下
执法缺口的加固。下文一切内容都标注了证据类型：**经典
单元**（在真实的实验应用上运行的攻击）、**模拟**（有
种子、可复现、生成器有文档）或**单元**（测试套件证据）。
未达到预先注册标准的声明会如实写明为失败，并附数字。

发布时套件：**585 个测试，583 通过，0 失败，2 跳过**
（先前已有的 RSA-PSS 互操作跳过项）。

## 第 1 部分 - 数学核心：随时有效的证据

### 1.1 旧基础的问题所在

随 2.6.0 一同发布的混合 GLR-CUSUM tripwire 积累证据的
能力很好，但它的阈值表（`r6-calib-1`）是在实验室模拟
轨迹上拟合的，并标注为未校准。因此关于它的每个误报
说法都是经验性的："在我们的模拟中，合法画像以 X 的
速率越界。"它的构造本身并不约束误报概率。2.7.0 新增
了一个证据引擎，其界限来自构造本身。

### 1.2 构造（`src/tier2-active/evalue-tripwire.ts`）

按 cohort、按 observe 步 t，引擎从该 cohort 已提供记录
的精确并集计算一个有界的提取强度分数：

    x_t = min(1, novel_t / SCALE)，SCALE 默认 = 50

其中 novel_t 是该步中对 cohort 并集而言为新的记录数。
一次 `observe()` 调用就是一步；步的粒度由主机选择
（这一选择是承重的--见 1.5）。

原假设是一个单一的、可解释的假设：

    (A1)  存在已知的 mu0 ∈ (0,1)，使得在合法使用下
          对所有 t 都有 E[x_t | F_{t-1}] <= mu0。

带可预测注额 lambda_t 的投注 e 值：

    e_t = 1 + lambda_t * (x_t - mu0)，K_t = prod_{s<=t} e_s

注额混合了一个固定的设计备择（mu1* = min(1, 2*mu0)，
Bernoulli 对数最优注额，减半作为下限）与一个只用过去
步数据的可预测插入式备择均值估计（收缩 kappa = 20），
并被裁剪到 [lambda_floor, 0.5/mu0]，使每个 e_t >= 0.5
且对数步有界。本金在对数空间中积累。API 不接受任何注
额输入：不可预测的注额在形状上不可能（有单元测试）。

**保证（乘积模式）。** 在 (A1) 下，对每条可预测注额
序列都有 E[e_t | F_{t-1}] <= 1，因此 K_t 是一个以
K_0 = 1 的非负上鞅，由 Ville 不等式

    P_H0( sup_t K_t >= 1/alpha ) <= alpha。

因此在首次越过 1/alpha 时标记，其误标记概率在**任何
停时**都 <= alpha--持续窥视和依赖数据的停止都包含在
保证之内。调整注额只能改变功效，永远不能改变有效性。

**确切声称的是什么：** 把随时有效的 e 值记账应用于
cohort 提取检测，具有这一保证结构，并与分层法律整合。
基础数学是已确立的（Ville 1939；Shafer 与 Vovk；
Ramdas、Grunwald、Vovk 与 Shafer 2023；e-detector：
Shin 与 Ramdas 2023；可预测插入投注：Orabona 与 Jun
2023），并不声称为新成果。

### 1.3 合并 cohort（规则，以及为何它是唯一规则）

当分组把多个身份关联起来时，cohort 随之合并。本金以
**加权平均**合并（权重 = 已观察步数），组成部分在合
并时冻结；合并后的 e 值乘到平均后的本金上。禁止乘积
和最大值合并。

为何平均能保持保证：在合并时刻 tau，每个被冻结的组
成部分相对于联合滤过是一个常数，而常数过程平凡地是
上鞅；非负上鞅的可预测凸组合是非负上鞅；且每个组成
部分都有 E[K_i,tau] <= 1（可选停止），因此合并后的
本金以期望 <= 1 开始。合并之后，有效性归结为合并后
cohort 自身对其合并后 e 值的 (A1)--与任何 cohort 相
同的条件。乘积规则行不通，因为没有独立性时
E[K_a * K_b] 不被 1 约束；最大值规则行不通，因为
E[max] >= 期望的最大值，方向反了。

### 1.4 模拟结果（预先注册，有种子）

标准在任何运行之前注册（PREREG-V270-MATH + 修正案 1，
后者由一轮外部红队推动）。生成器镜像校准拟合器的画像
家族（种子 0xC0FFEE 谱系；分数模拟种子 20271102）。完
整记录：研究侧 `v261/t1-results.md`、`t1-sim-raw.json`。

**有效性（M1）--通过。** 10,000 次合法运行，每步检查
本金，时域 2,000：在 alpha 0.05 和 0.01 下 **0 次曾
越界**（单侧 95% Clopper-Pearson 上界 0.00030，标准为
0.065 / 0.020）。最不利原假设（真实均值恰为 mu0，低
方差形状）：13/4,000 = 0.325%。

**方差压力下的有效性（探针 M1b）。** 方差**最大**的
最不利原假设（x_t ∈ {0,1}，P(1) = mu0--对 Ville 压
力最大的形状）在名义 5% 下以 **4.175%** 越界
（167/4,000，中位越界步 54）。保证在真实边界处接近
紧致；上文低方差的保守性是那些原假设方差的性质，不
是可花的余量。

**检出（M2）--部分通过，按预先定义。** 对照已发布
CUSUM 在同一批拟合器轨迹上的行为（框架说明见下）：
切片轨迹--e 引擎以中位数 **400** 条并集记录越界，
CUSUM 为 1,225，两者都是 16/16。按条记录喂入的 ID
遍历轨迹--e 引擎 **0/16**：单条记录的步分数 x = 0.02，
比 mu0 低一个数量级，因此新并集分数在请求粒度上对细
节通道是结构性盲的。分数级运行（批量步，E[x] = 0.26）
以中位数 917.5 条记录 1,000/1,000 越界。按注册规则，
部分通过意味着：该引擎作为**可选的保证路径**发布；
CUSUM 仍是默认；任何地方都不用"替代"字样。

关于 CUSUM 对照的公平说明（应红队要求，两个方向都
写）：把生产 CUSUM 的已发布默认值重放在拟合器的轨迹
家族上，其经验原假设越界率在名义 1e-3 下为 0.50（NAT
和新用户家族 16/16 越界）--而 2.5.0/2.6.0 的经典单
元在产品接线粒度上显示同一个 CUSUM 守住了它的对照
组。两个事实都关乎粒度和校准拟合，而不是哪个引擎
"更好"：轨迹实验按条记录喂事件；经典实验喂产品形状
的请求。步粒度同时移动两个引擎的合法均值和攻击均
值，这正是 2.7.0 写明粒度契约（1.5）而不是宣布赢家
的原因。

**误设代价（M3，无标准--数字本身就是重点）。** 真
实合法均值在 mu0 + 0.05：**1,500/1,500 越界**（中位
数 86 步）。在 mu0 + 0.10：1,500/1,500（中位数 42）。
批量导入合法画像（E[x] = 0.36 > mu0）：1,000/1,000，
中位数 26 步。(A1) 不是一个软假设：合法持续强度超过
界限的 cohort 类别**一定会被**标记，长时域下概率接
近 1。第 1.7 节正是因为这张表而存在。

**诚实下限。** 一个持续在 mu0 恰下方运行的攻击者
（E[x] = 0.18）越界 0/2,000--按构造在 H0 之内。引
擎对界限以下的东西是盲的，这是设计；这种盲是 1.9
节模仿下限在分数空间中的重述。

**多重性（写明，未解决）。** Ville 是按 cohort 的。
在 N 个合法 cohort 上，一生误标记的期望数约为
N*alpha，P(至少一个) 约为 1 - (1-alpha)^N：在
alpha = 0.05、N = 100 时，约 5 次期望误标记且
P >= 99%。主机必须在自己的 cohort 群体上预算 alpha。
舰队级预算（在线 FDR / alpha 投资）是排名第一的下
一波候选。

### 1.5 步粒度契约

没有写明的步定义，mu0 毫无意义。把同样的轨迹以 60
秒窗口喂入，e 引擎能抓到 ID 遍历（16/16，中位并集
331.5）--同时也让合法的重度读者、NAT 和新用户轨迹
16/16 越界，因为它们每分钟的新并集均值超过
mu0 * SCALE：在那个粒度上 (A1) 对它们不成立。模块头
中发布的契约：一次 observe() 调用就是一步；按您实际
喂入的粒度设定 mu0；批处理是安全配置的一部分，不是
接线细节。

### 1.6 Shiryaev-Roberts 模式（S1）--本金债务的修复

纯乘积过程没有清白下限：1,000 个安静步以 e ~ 0.9 把
对数本金压到约 -105，之后开始的攻击必须先偿还这笔
债务。在注册的"先静默后攻击"流上测得：乘积模式以中
位数 **774 个攻击步**越界，而在新 cohort 上是 17 步
（约 45 倍）。

因此该模块还发布了一个 SR e-detector 模式
（`detector: "sr"`）：M_0 = 0，M_n = (1 + M_{n-1}) * e_n，
作用于同一批 e 值（等价于对所有重启点的分段乘积求
和），在对数空间中跟踪。它的保证形状**不同**，且从
不与 Ville 混淆：在 (A1) 下，E_0[M_n] <= n，误报的
期望时间满足 E_0[tau_B] >= B--**平均运行长度控制**，
B（`srThreshold`，默认 1,000）是 ARL 旋钮。

测量（PREREG-S1S3 标准 D1-D3，全部通过）：先静默后
攻击中位数 **14 个攻击步**（标准 <= 155；比乘积模式
好约 55 倍），500/500 越界；新鲜切片中位数 **356 条
记录**（乘积模式在相同运行中 379；标准 <= 1.25 倍）；
原假设总测试时间在 B = 100 时为每次越界 **513 步**，
B = 1,000 时为 **5,376 步**（标准 >= B/2），且所有越
界都集中在最不利家族--它自己的 ARL 就在边界附近
（B = 100 时 102.7），即 SR 界限恰好在乘积界限保守
的地方接近紧致。头部带有的注意事项：cohort 合并之
后，SR 统计量是组成部分的步加权平均，那里的 ARL 读
数是近似的。

主机应该运行哪种模式？当标记喂给一个需要最强误标
记说法的后果、且 cohort 持续活跃时，用乘积模式；当
cohort 有长安静历史、或威胁模型是休眠后爆发时，用
SR 模式。CUSUM 仍是默认的校准路径；两种 e 模式都是
可选的证据来源，喂给同一套分层法律。

### 1.7 设定 mu0--以及 `calibrateMu0`（S3）

mu0 必须约束引擎所指向的每个 cohort 类别的合法持续
强度，按主机的步粒度。流程：(1) 选定步定义（一次
observe() 调用携带什么）；(2) 按 cohort 类别在主机
的合法流量上测量每步分数（纵向农场正是为收集这个
而存在）；(3) 从测得的分布带余量地按类别设定 mu0
--或使用附带的助手；(4) 给合法地跑得热的类别（批
量导入、合规爬取）它们自己的界限，或分层法律已经
置于推断后果之外的声明/受保护通道。

`calibrateMu0(scores, { delta })` 把步骤 (3) 实现为
一个分割共形界限：它返回校准分数在 1 - delta 水平
的共形上次序统计量 q，以及 mu0 = min(1, q + delta)。
推导：对 x ∈ [0,1]，只要 P(x <= q) >= 1 - delta，就
有 E[x] <= q + delta，而共形次序统计量在校准分数可
交换的条件下给出有限样本、无分布的覆盖。测量（标
准 C1-C3）：合并校准（n = 320,000）给出在 delta
0.05 时 q = 0.18、mu0 = 0.23（留出超出率 4.23%，CP
上界 4.27% <= 6%），在 delta 0.01 时 q = 0.22、
mu0 = 0.23（CP 上界 0.15% <= 2%）；留出的各家族均
值全部 <= 0.23（普通 0.080，重度 0.140，新用户
0.065，NAT 聚合 0.121）；引擎在 alpha 0.05、用助手
的 mu0 时，每个家族的留出运行都 0/200 越界。写明的
限制：共形保证是边际的、合并的--合并校准不覆盖各
家族的超出率（NAT 聚合在 delta 0.05 时步超出率
11.6%，而其均值远在 mu0 之下），因此有明显不同流量
家族的主机应按家族校准；而校准一个均值界限并不能
免除 (A1) 对合法的对抗性定时突发流量的条件形式
--M3 表仍然是价目表。

### 1.8 跨检测器的证据记账（原则，S2）

antiRea 现在在一条流上运行多个证据消费者（CUSUM、
e 过程/SR、群体检测器、评审钩子）。本波采用差分隐私
的组合纪律作为该栈的原则：证据像隐私损失一样组合
--运行 k 个检测器的主机是在花同一份误报概率预算
和同一个观察池，同一个观察绝不能被当作独立证据重
复计数（所有者在 2.4.0 为咨询评审钩子定下的规则是
其本地实例）。过滤器和里程表（收获：Rogers 等；
Whitehouse 等）是操作形状：里程表报告累计花费，过
滤器在预算处停下。实现这一点的组合检测器包装是下
一波候选；在 2.7.0 中它是文档，不是代码。

### 1.9 边界定理（T4），正确陈述

**定理（模仿界限）。** 设防御者的决策规则只能看到
请求记录。设 P_L、P_A 分别为合法用户和攻击者诱导
的记录分布。对任何在合法流量上拦截率 <= alpha、在
攻击者上通过率 >= beta 的规则：

    |beta - alpha| <= TV(P_A, P_L)。

**推论（泄漏下限）。** 一个能从最快被许可的合法工
作流中采样记录的攻击者，以该工作流的速率实现提
取，通过概率至少为 1 - alpha -（采样误差）；观察
同一批记录的任何计量层都做不到更好。

假设，完整：(i) 防御者观察不到记录之外的任何东西
（没有带外身份成本，没有客户端证明）；(ii) 攻击者
能以某种成本进行模仿；(iii) **记录模型覆盖提取可
能发生的通道**--未计量的表面不是该界限的反例，它
在界限的范围之外（那里的提取根本不受约束，只是无
人观察）。交互：T1 不移动这一界限（它控制原假设下
的误报；该界限管辖模仿下限）；信息加权预算（T2）
重新参数化泄漏轴，界限的形状不变。定理的操作内容
与一直以来驱动设计的内容相同：唯一能移动下限的杠
杆是身份成本和权利范围--两者都是主机决定。这正
是 ID 遍历残余（2.6 节）仍是一个主机决定关卡的
原因。

### 1.10 被搁置的数学候选

- **T2，信息预算。** 已在研究文档中形式化；搁置是
  因为已发布的并集计数已经是不同物品覆盖的退化信息
  度量，而真正的 MI 估计器需要一个 SDK 有意不持有
  的数据集模型。第一个诚实步骤（主机标记的加权并
  集）是已排名的下一波候选。
- **T3，博弈论定价。** 极小极大推导给出已发布的节
  奏**形状**；其常数从假设中返回。分析保留，构建在
  综合中被否决。
- **舰队 FDR 预算**（在 cohort 上做在线 alpha 投
  资）--排名第一的下一波候选；见 1.4 多重性。

## 第 2 部分 - 加固轨道

### 2.1 L1 - 声明上限竞态：已关闭

2.5.0 经典单元在顺序接线中证明了声明上限精确
（600）；LIMITATIONS 把并行情形记为未测量。单元
（40 个并发 worker，上限 600，18 个身份，5-25 ms 提
供延迟）："先检查后提供"路径超到了并集 **639**
（1 条记录形状）和 **1,575**（25 条记录形状）。修复
是在 tripwire 本身上做基于预留的执行：`reserveServe`
（同步检查 + 暂定预留在一次运行到底的步中完成）、
`commitServe`、`releaseServe`，以及
`ceilingReservation.ttlMs`（默认 60,000）。重跑：
**精确 600，零超出，两种形状**，40/40 个 worker 在
上限处被拒绝；已声明受保护的对照组 1,200/1,200，
零干扰。18 个单元测试覆盖一个外部红队逼出来的契
约：一个在其预留过期后到达的提交会被以
`reservation_expired` 拒绝，且永远不能复活已释放的
容量（结算墓碑）；TTL 必须超过主机最坏情形的提供
延迟，在有效预留之外提供不在上限承诺之内--两者都
写在模块头中。范围上的诚实：这为提供过程走**一个**
SDK 进程的主机关闭了竞态；跨进程精确性是账本的工
作（2.2）。

### 2.2 L3 - 分布式存储：参考实现 + 工具包

`examples/sqlite-ledger-store/` 发布了一个基于 Node
内置 `node:sqlite` 的事务型存储（WAL + BEGIN
IMMEDIATE CAS，作用于 SDK 读取的同一个
`antirea:ledger:<id>` 键），以及一个任何主机存储都
可被评级的符合性工具包。跨进程证明：2 个进程，1 个
共享文件，上限 100，请求 400--合计授权**精确
100，超出 0**，经第三个连接核验，三次重复运行总
数一致。工具包让内存和 sqlite 存储 4/4 通过，并让
一个故意说谎的 get/put 存储以具名理由
`DISHONEST_TRANSACTION_CLAIM` 失败。诚实的注意事
项：精确性已证明，**公平性没有**（跨进程的授权分
配跑出 0/100、0/100、100/0、10/90--需要公平性的主
机必须加自己的调度），且 node:sqlite 需要 Node
>= 22.5 而 SDK 支持 >= 20，这正是该存储住在
examples/ 而不是 src/ 的原因。

### 2.3 L9 - Web Bot Auth 一致性包

16 个新测试从 RFC 的示例密钥材料独立构建 RFC 9421
签名基（没有复制任何厂商的成品），并对
`createWebBotAuthVerifier` 运行：3/3 个有效向量验
证通过；**12/12 个无效向量以具名理由被拒绝，误接
受数为 0**--包括一个在与所呈现消息**不同**的消息
上有效的签名（2026 年 10 月一份独立分析在 Visa TAP
和 Mastercard Agent Pay 的已发布示例中发现的失效模
式）、对着一个紧的最大值配置的恰为 60 分钟有效窗
口的 TAP 形状、nonce 重放、重复的被覆盖组件、
expires <= created。没有发现验证器缺陷；该包现在
永久运行在 `npm run check` 中。

### 2.4 L10 - 政策信号包

`createPolicySignals`（新模块）生成诚实的声明层：
robots.txt 的 `Content-Signal` 行（Cloudflare，2025
年 9 月）和 `Content-Usage` 行（IETF aipref 草案词
汇）、一个 TDMRep `/.well-known/tdmrep.json` 文档
（W3C CG 最终报告--一个由规则对象组成的 JSON 数
组；模块遵循报告，而不是单对象简写），以及一个把
它们与 `enforcement: "none"` 绑在一起的 antiRea 政
策 JSON。它声明**主机**的选择（选择加入训练是完全
可表达的），以具名错误验证输入，并且只声称**格式
符合性**：今天没有已知的主要爬虫消费 Content-
Signal，因此任何地方都不声称有偏转效果。

### 2.5 L4 - 功能侧单元 S2/S3，以及 L4-F1 缺陷

在 2.6.0 功能实验台上的新经典单元（标准预先注册）。
**S2 繁重搜索**（16 个身份平铺 40 个语料切片）：标
记覆盖 **10/16**（标准 >= 10），完成度 **12/40 =
30%**（标准 <= 40%），对照标准**失败**--而该失败
是一个真实缺陷，不是测量假象（见下）。**S3 促销
farming**（12 个身份）：标记 **12/12**，32 个 cohort
信用，每个身份的授权被限制在每 60 秒窗口 2-3 次
（界限 20），86 次标记后中断，对照组的第一次领取
干净--全部标准通过。

**L4-F1（实现缺陷，在本版中修复）。** 操作 cohort
跟踪器的互补合并按聚合体计重叠分数，因此一个其唯
一目标与某个群体目标重复的单例簇，以恰好 0.10 的比
率被吸收进群体。两个测得的后果：旁观者对照组落入
标记快照**之内**，且被吸收的重复把该群体成员的唯
一目标计数清零--因此基于贡献的摩擦定位完全跳过了
那个攻击者（0 次中断，它的 3 次操作全部完成）。修
复（先于代码注册的修正案）：互补合并/加入现在要求
较小一方贡献至少一个对并集**新**的目标，或携带至
少 2 个实例--零新目标的单例不携带任何分组证据。
以相同的驱动器和标准重跑：S2 (a) 通过 10/16，(b)
通过 **25.0%**，(c) 通过--对照组不在任何快照中，
先前被庇护的攻击者被 enroll 并有 2 次中断，**16/16**
个攻击者被 enroll；S3 不变，通过。共享目标机制被有
意保持原样。

### 2.6 L5/L6/L7/L8 - 较小的事项，如实陈述

- **L5，功能侧 LLM 攻击者（单个模型）。** SambaNova
  gemma-4-31B-it，对导出单元运行 2 次：两次都是
  **16/80（20%）**，24/24 被 enroll，1.5M 上限中的
  16,051 个 token。该模型独立选择了脚本化群体的分
  配并精确匹配其结果；它从未尝试其提示中描述的地
  板之下反策略。两次运行是一个轨迹的可靠性重复，
  不是独立的战略样本--与数据侧那波相同的注意事项。
- **L6，ID 遍历残余：未变，主机决定关卡。** 在推断
  cohort 法律下仍是 90.0%（18 x 500 / 10,000）。每个
  合法角度都被重新审查（更快的检出增加中断，不移动
  下限；更严厉的推断节奏会重新定价摩擦层级)。关卡
  是权利决定，或主机侧的声明 cohort / 上限清单
  --2.7.0 使其竞态精确（2.1）。两位外部评审都同意
  这一分类；一个通过重新调参把数字"改进"到 85% 的
  建议被拒绝（它会移动法律钉死的下限常数）。
- **L7，CUSUM 校准：仅就绪。** 已发布的拟合器在纵向
  农场迄今的数据上端到端运行约 9 秒（农场第 1 天：
  6,953 个事件，44 个身份，58,849 次记录提供），并
  复现其有文档记录的提议（保留 r6）。拟合器尚不能
  消费农场轨迹；适配器已定范围（约 150-250 行），
  第一次诚实的拟合需要整整两周的农场数据--**最早
  约 2026-11-16**，第 3 周留出数据的结论在
  约 2026-11-23。2.7.0 中没有拟合任何表；在稀薄数
  据上拟合是预先注册禁止的。
- **L8 清扫。** (a) `onConsequenceEligibility` 回调
  在每个 cohort 从不合格到合格的转变上恰好触发一
  次（主机不再轮询快照）。(b) 群体检测器获得一个可
  选的 `unionGrowth` 权重（默认 0；已发布的计分逐
  位不变）：权重 0.15 时，一个合成的交错规避者在恰
  好 60.0 处被标记，而默认峰值为 57.3--且合法同事
  对照组的峰值升到 58.1，接近阈值，这正是它保持可
  选的原因。(c) 金丝雀回声验证在轮换期间接受前一个
  密钥的窗口，每个结果上都标注代次。(d) 操作预算
  跨进程的覆盖可见性已被测量，现在是一个有文档的
  契约，并有 `flushOverrides()` 做显式发布。外加两
  个缺失的操作层单元测试（金丝雀污染过期；共享目
  标的补充公告）--两个行为本来就是正确的；缺口在
  测试覆盖中，LIMITATIONS 此前一直如此写明。

### 2.7 金丝雀放置规则（原则，S4）

## 第 3 部分 - 咨询性覆盖信号与宽限期

第 1-2 部分描述 2026-11-02 的开发波。三个模块在其
后构建，来自 HARVEST2 研究队列，遵循同一纪律：先
在实验室预先注册淘汰标准，实验室通过后才做构建决
定，且凡测量显示有伤害合法用户的途径之处，硬条件
都在代码中--不在文档中。

### 3.1 输入空间覆盖 - C6（`createInputSpaceCoverage`)

**实验室结论：通过（本波第一个通过关卡的候选）。**
记录覆盖机制（CUSUM 流、群体并集）测量一个身份或
cohort 取走了数据集的*多少*。它对停留在合法功能
内、合法流量下的枚举是结构性盲的--P10 形状：一个
群体横扫搜索/过滤功能的输入空间，每个成员都礼
貌，*记录*并集毫无异常。C6 在输入空间本身（功能
参数、资源 id）上积累覆盖统计，分两个家族（F：功
能空间，R：资源空间），在身份和 cohort 层级以计
入并列的共形积累计分。

实验室数字（3 个种子，harness-v2 群体；标准预先注
册）：合法标记率合并 VALID **1.26%**，标准 2.0%
（F 1.05% / R 0.76%）；促销周 **1.20%**--积累覆盖
统计**不**被合法的促销尖峰毒化，那正是杀死 C3 的
机制；声明的大批量 cohort 在自己的池上校准为
**0.50%**，标准 1%。锋芒：横扫 **9/9** 与随机探测
**9/9**，在第一个检查点（20 次查询）即被标记，
而基线 novel-CUSUM 两者都是 **0/9**；通过功能分
散的群体被标记 **72/72 个成员加 cohort 3/3**，而
并集资源对照是 **0/3**。规避者代价，已测量：放慢
的横扫仍在第一个检查点被标记（时间因子约
10,000 倍）；一个被限制在 120 个 id 子集（6% 提取
上限）的轮换者在延迟 356-500 时被标记，因为它的
distinct 率落到合法下限**以下**；诊断价格曲线在约
2.9 倍子集大小处标记。在经典资源形状上，该模块
诚实地比基线慢：ID 遍历/切片 cohort 会被标记，但
在 480-816 个事件处，而基线是 11-13 步--覆盖集形
状是慢证据。

**SDK 复核（已发布的模块，相同群体与种子）：**
VALID 误标记率 **1.15%**（F 0.78% / R 0.36%），促
销 **1.08%**，大批量 **0.50%**；横扫/随机探测/慢横
扫在第 20 次查询 9/9；分散群体 72/72 + cohort 3/3，
并集对照 3/3 全盲；ID 遍历资源家族延迟 608-688 个
事件。套件成本：每检查点 p99 0.0018 ms（F）/
0.0027 ms（R）。

**代码中的硬条件**（每一个都是一次实验室测量，不
是偏好）：主机必须声明其可枚举表面--没有声明，
实例被禁用，不给任何人计分；声明之外的功能永远
不被计分。声明的（大批量）cohort 被路由到自己的
校准池，在该池拟合之前报告 `uncalibrated`--它们
永不回落到普通池，因为用普通池给大批量流量计分
在实验室测得 **100% 误标记**。池下限（50 条流 /
30 个 cohort）会抛错，而不是在太少的数据上校准。
输出是一个咨询信号（`enforcement: "none"`）；一个
测试钉死了 API 表面--不存在拦截或决策函数。

**C6-1--已在清理波中结案（4.6）。** 发布前审计复
现了声明 cohort 路由按身份锁存：一个在检查点带声
明 cohortId 的查询会把该身份的整条流移入声明通
道，包括它先前未标记的查询。这个问题最终在 SDK
层即可判定--实验室设计把声明 cohort 定义为一条
独立的校准流，本就不要求静态成员资格--因此该案
例被确认并修复：路由现在是每个事件的函数（带声
明 cohortId 的查询在该身份的大批量通道计分；任
何其他查询在普通通道计分），状态按（身份 × 功能
× 通道）拆分，检查点按通道关闭，且硬性条件在逐
查询粒度上存续--大批量流量仍永不用普通池计分。
修复后，已发布模块的完整实验室复检与修复前逐字
节相同（VALID 1.147% / 销售 1.083% / 大批量
0.50%；扫描与随机探测在第一个检查点 9/9；兽群
72/72 + cohort 3/3）。只有混合标记的身份会看到
行为差异；单通道身份不受影响。

### 3.2 资源/referrer 画像 - C9（`createAssetReferrerProfile`)

**实验室结论：通过，作为一个永久封顶的辅助功
能。** 抓取型浏览器通常每页加载约 0.3 张图片，
约 98.4% 的时间发送空 referrer；校准语料中的合
法浏览器每页加载约 22 张图片，空 referrer 约 5%。
C9 在固定时域（50 页 / 120 页合并）以单侧、计入并
列的共形 p 值，对这两个通道的按身份和按 cohort
均值计分，**外加**一道也必须通过的分离门：标记
要求分数超过阈值**且**该身份的图片均值不高于一
道门**且**其空 referrer 占比不低于一道门，两道
门都从 TRAIN 极值对照已发布的机器人画像导出。

其解剖结构写在实验室结果中，且比标题更重要：
FP=0 的结果是分离门扛起来的。纯共形分数本身标记
1.23% 的合法流（在 alpha 0.01 下恰为名义值）；门
挡下了全部 82 个。边距很宽--合法图片均值最小
15.32，对照约 2.2 的门（6.9 倍），合法 referrer 占
比最大 0.18，对照门 0.582。标题实验室数字：
VALID **0/6,658**，促销 **0/923**，cohort
**0/150**；锋芒：原始 9/9、礼貌 9/9、天真回访 9/9
（基线只抓到回访形状的 6/9）；单命中群体以 cohort
形式 3/3 被抓，那是按算术在每身份层面不可见的形
状。成本每计分 p99 0.004-0.007 ms。

**封顶是结论的一部分。** 一个伪造完整画像（加载
图片、发送 referrer）的规避者能逃过 C9 本身 0/9
--但整个系统仍通过其他层抓到它 9/9，而伪造的代
价是原始机器人 **22.8 倍**的带宽（合法浏览器的
1.03 倍）。因此 C9 是对规避行为的一种带宽税，被
禁止提升为独立的检测器。

**代码中的硬条件：** 分层是承重的。主机必须声明
哪些流量类别是中性的（API 客户端、已声明的自动
化）；只有被声明的浏览器层才会被计分或积累。若
按浏览器计分，API 客户端在实验室被标记
**1,500/1,500（100%）**；声明分层之后，为 0。没
有声明：模块自我禁用。

**发布时比注册的实验室设计更紧（03/11）。** 在实
验室通过后、按所有者要求增加了两个机制，并在发
布前用已发布模块在实验室规模上重新测量：(a) 门
安全边距--`gateSafetyMargin` 默认 0.25，把两道
门都推离合法区域约 4 倍于唯一一次观察到的训练到
验证极值漂移（图片均值 5.7%，referrer 占比 0%）；
加边距后门位于图片均值 1.655 / referrer 占比
0.686，仍远离机器人画像（0.3 / 0.984）；(b) 双窗
口持续性--计分在连续不重叠的窗口中运行，第一个
违规窗口产生 `watch`，标记要求**两个连续**违规
窗口，一个干净窗口即重置。用收紧后的模块做实验
室复核：VALID **0 标记、0 watch / 6,658**，促销
0/923，cohort 0/150--实验室的零完好无损，包括在
watch 层级。代价，已测量并印出：身份标记从第 50
页移到第 **100** 页，cohort 标记从 120 页移到
**240** 页合并页，而单窗口的单命中群体现在只到
watch（3/3）而不是标记--这是有意用单窗口形状换
取第二次独立确认的交易。

**诚实的限制：** FP=0 是一个实验台数字。现实中恰
好坐在机器人角落的合法子群体--禁用图片、文本浏
览器、RSS 阅读器、referrer 拦截器、未声明的合法
客户端--实验台**不**生成它们，因此**不**被测
量。该子群体的规模只能在真实主机日志上测量；它
记录在 LIMITATIONS 中，是该模块的长期条件。

### 3.3 验证后宽限（`createVerificationGrace`)

于 03/11 构建，源于所有者指出的一个缺口：在此模
块之前，只要合法用户的（合法）行为模式保持热
度，没有任何东西阻止系统在每一个新的越界处重新
挑战同一个人。宽限是主机后果层的一个按身份记
录--与受保护 cohort 门同一层，有意**不**放在任何
引擎内部：引擎全程继续计分和标记；只有 step-up
的 **enroll** 被门控。

契约：当一个身份通过 step-up 挑战时，主机调用
`recordVerified`，并在 enroll 重复 step-up 之前咨
询 `guardStepUp`。在窗口内（默认 **24 小时**，参
数范围 1 秒 - 30 天），普通证据水平的重复 step-up
塌缩为 `observe`。宽限在证据达到升级线--默认
**2 倍**标记阈值--的那一刻失效，且失效会**锁
存**：跌回线下不会恢复宽限；只有一次新的通过
step-up 才开启新窗口。（没有锁存，攻击者可以在
线附近爆发-下潜-爆发，升级阈值就毫无意义。）所
有窗口算术都在单调间隔时钟上运行（L-DEEP-2 纪
律）：墙钟步进既不拉长也不缩短窗口；墙上时间只
保留为审计时间戳。状态上限 2,000 个身份，驱逐偏
向**更多**摩擦（一份丢失的宽限记录），永不更
少。无效证据（NaN/Infinity）产生结构化的
`invalid_evidence` 结果，不抑制任何东西也不变更
任何东西--F-09 的教训在出生时就应用了。

结构性保证，由一个在模块旁接了真实记录预算（上
限 5）的测试钉死：一个在宽限内的身份和一个对照
身份都在恰好第 6 条记录处被拒绝--**宽限买到 0
条记录**。该模块不持有对任何预算、配额或上限的
引用（单向，如评审通道），因此它不可能抬高其中
任何一个。不声称的是：24 小时窗口和 2 倍因子是
政策参数，锚定在代码库既有的每日节奏和 LLR 算术
上（把一个界限翻倍即把似然比平方--是决定性的升
级，不是边缘噪声）；两者都未在真实流量上校准，
且尚无生产部署测量过宽限存在之前重复 step-up 实
际触发了多少次。

### 4.1 被移植的修复状态（F-01..F-16 + L-DEEP-2）

按行为加测试移植，从不覆盖文件--2.7 的模块在同
一批文件之上承载新代码。F-01 两个账本中的
idempotency 指纹（主体 + 载荷）与
`idempotency_conflict` 拒绝；F-02 通过
`recordIfBelow` 的原子配额执行，以及面向传统存储
的 `atomicEnforcement` 诚实标志；F-03 导出最坏情
况预留（2 倍估计行数，在结算时释放）；F-04
CSV/流式正文计价（包裹 write、在整个正文上结
算、按估计或下限的平价）；F-05 无定价操作默认以
`unknown_action` 被拒绝；F-06 账本失败关闭式错误
处理（`store_conflict` 真正被返回）；F-07 稀疏账
本位图（10^8 的 id 不再分配约 16.7 MB）；F-08 带
待发与重试投递的战役标记与防抛谓词；F-09
`checkServe` 输入验证（`invalid_request`）、自愈
补充、`clearCohort` 时重置桶；F-10 CUSUM 状态上
限（`maxIdentities` 2,000、LRU、快照中的
`stateSizes`）；F-11 纪元轮换重置分数 + 贡献 + 待
发状态；F-12..F-13 idempotency/主体生命周期的清
理；**F-14（行为改变）：**一个预算身份无法解析
的导出被计入一个共享的 `unknown:unresolved` 桶，
而不是悄悄跳过预算--传统的跳过是显式的可选
`allowUnresolvedIdentity`，与配额守卫已经使用的
同一种失败即响亮模式；**F-15（行为改变）：**长
于 1,024 个字符的 id 的记录预算键从有界样本（头
部、尾部、全长）哈希--每个 id 的哈希成本是常
数，而不是对一个 2M 字符 id 的约 160-220 ms，代
价是病理 id 的碰撞家族更宽（且已被接受）；F-16
在任何状态被触碰之前结构化拒绝畸形 CUSUM 事件。
L-DEEP-2 单调纪律（12 个点）随它们一并移植--在
被审计的树中只有 verification-grace 还保留着它
（审计 CLK-1）；账本中的预留已经使用双层规则，
4.2 把它扩展到唯一还缺的地方。

**复测：** 每一个审计实验台都在修复后的树上重
跑，并达到了其预先注册的通过标准（审计的复测注
意事项表）：陌生重放被拒绝，而相同重放仍返回
`duplicate: true`；原子存储精确守住 5/12，而传统
存储携带 false 标志；并行导出在上限处或其下结
算；四个正文路径全部计价；无定价授予 0/30；损坏
的存储拒绝而不是抛错；极端 id 有界；标记在回调
抛错后被重新投递；10 -> NaN -> 10 -> 10 序列健
康；状态有上限且报告 `stateSizes`；+90 天时无即时
再越界；+5 分钟墙钟步进不再补满已花光的预算。修
复波自己的测试随之移植：本波中套件从 424 个测试增
长到 520 个，清理波（4.6）之后增长到 585 个。

### 4.2 CLK-2 - 预留 TTL 在运行的时钟上

**2.7 代码中的新发现，MEDIUM，发布前已修复。**
`reserveServe` 只用墙钟计算预留过期：+61 秒的墙
钟步进（TTL 默认 60 秒，实际时间约 0 ms）让一个
活着的预留过期，第二个完整预留被授予，已声明的
50 条硬上限被越到并集 100--而第一个把每一步都做
对了的主机，其提交被以 `reservation_expired` 拒
绝。审计对该模块"TTL 契约 = 主机违约"辩护的反驳
成立：该契约假定**真实**提供时间超过 TTL；这里
过期的唯一原因是时钟步进，一个主机既不引起也不
控制的事件。

修复应用了所有者已经为账本预留批准的规则：一个
预留在**先到者**处死亡--它的墙钟过期**或**它的
单调已流逝 TTL（`createdMonoMs` 记在内存中，
`monoNow` 可注入）。选择锚定单调的过期、而不是任
一纯时钟的运行理由：纯墙钟过期恰恰是上面的失
败（NTP 步进或 VM 时间校正能制造或摧毁容量）；
纯单调过期在进程重启后无法重建，且与主机在日志
和清单中对账的墙上时间戳漂移。在两者中较早者处
死亡，能在两种失效模式下都守住预留的承诺：没有
步进能把预留拉长超过其 TTL（单调已流逝对步进免
疫），也没有预留能活过主机公布的墙上截止时间。
复测：只有墙钟步进时，第二个预留被拒绝
（`campaign_ceiling`），并集精确停在 50，第一个
预留的提交成功；一次真正很长的提供仍按真实流逝
时间过期。

### 4.3 EV-1 - e 值回调：异步拒绝被吞没

**2.7 代码中的新发现，MEDIUM，发布前已修复。**
e 值引擎把 `onCross` / `onSrCross` 包在同步
try/catch 中，而它的接口承诺"错误被吞没"，其头
部写明主机接线绝不能破坏请求处理。一个异步回调
若 reject，会以 **未处理的 rejection** 逃出--在
默认 Node 进程上即崩溃--且恰好在越界的那一刻。
修复采用了 CUSUM 的 `onConsequenceEligibility` 在
同一棵树中已经使用的模式：捕获回调的返回值，并
给任何 thenable 附上一个吞没错误的 `.catch()`。
复测：审计实验台捕获到 **0** 个未处理 rejection，
越界决定仍被交付。

### 4.4 EV-2 / EV-3 - e 值输入卫生与校准可组合性

**两者都是 LOW，两者都在发布前修复。** EV-2：
构造器的 `!(scaleRecords >= 1)` 检查放行了
`Infinity`（`shrinkKappa = Infinity` 以同样方式通
过其 `> 0` 检查），此后每个分数都算成 0，引擎永
久地、悄无声息地失明--200 个最大步，无越界，无
错误。两个选项现在都要求 `Number.isFinite`，并
在构造时抛出具名的 `RangeError`（构造器本来就是
这样检查 `srThreshold` 的；这两个选项只是被漏
掉）。EV-3：`calibrateMu0` 能返回 `mu0 = 1`--一
个 `createEvalueTripwire` 自己拒绝的值--因此校
准助手的输出并不总是能被它喂养的引擎使用。该助
手现在把返回值封顶在 1 以下，并在共形界限饱和
（分位数 + delta >= 1）时给结果加上
`saturated: true` 标志：该值是引擎可接受的输
入，但明确**不是**一个已证明的界限，这是对饱和
校准的诚实描述。

### 4.5 KIT-1 - 符合性工具包按文档运行

sqlite 存储的符合性工具包，按其 README 的确切记
载调用（工厂路径，无 `--label`）时，打印了用法
消息并以 2 退出：当 `labelIdx = -1` 时，参数扫描
排除了索引 0--即工厂路径本身。已在参数解析器中
修复（label 值索引仅在 `--label` 存在时适用）；
已实际验证：sqlite 和内存固件 4/4 通过，说谎的
get/put 固件以 `DISHONEST_TRANSACTION_CLAIM` 失
败，`--label` 仍可用，真正无参数的调用仍以退出
码 2 打印用法。

### 4.6 清理波--关闭审计的其余部分

合并之后，还剩三个桶：以 needs_validation 存在的
C6-1、2.6.0 审计的低严重性残余 F-17..F-24，以及
该审计的四个 needs_validation 案例 NV-1..NV-4。
最后一波清理在这棵树上逐一复核了它们：十三个全
部复现，十三个全部修复，套件从 520 增长到 **585
个测试**（+65 个回归测试，每个都有修复前失败 /
修复后通过的证据）。审计范围内不再有未决的
needs_validation 案例。

**C6-1--已确认，按事件修复。** 路由问题无需主
机事实即可判定：实验室设计把声明 cohort 定义为
它自己的校准流，而不是静态成员资格，因此锁存是
缺陷。路由现在是每个事件的函数--带声明
`cohortId` 的查询在该身份的大批量通道计分，其他
任何查询在普通通道计分；状态按（身份 × 功能 ×
通道）拆分；检查点按通道关闭；`evaluateCohort`
只聚合普通通道；资源事件上的 `cohortId` 不再路
由查询。硬性条件（永不用普通池给大批量流量计
分）逐查询存续。修复后已发布模块的实验室复检与
修复前逐字节相同：VALID 1.147%、销售 1.083%、大
批量 0.50%、扫描/随机探测在延迟 20 时 9/9、兽群
72/72 + cohort 3/3--没有单元退化。单通道身份看
不到任何变化。

**F-17..F-24--全部确认，全部修复。** F-17：
`evaluateAction` 现在只评判一个组在活动窗口内仍
存活的那一片（纯读取），因此已死组的标记永远不
会被报为陈旧。F-18：动作 cohort 跟踪器在观察和
读取时修剪每一张映射（`pruneAll`）。F-19：
`evidence-attribution` 新增 `maxPairs` 选项，默
认 **1,024** 对，带 LRU 淘汰--超过上限时，被淘
汰对的交叉信用被遗忘并从零重启。F-20：主机回调
在余下的裸露位置被包进本包的吞没纪律（兽群的
`recordIndex` / `getLimit`、动作 cohort 的
`getAllowance`、流量评分器的 `isExempt`）--抛错
的回调不再能中断一次观察或留下半变异状态，且非
布尔的真值 `isExempt` 结果现在计为不豁免，与
CUSUM 的先例一致。F-21：两个兽群模块在触碰任何
状态之前先验证事件时间戳--非有限的 `ts` 或 |ts|
超出 Date 范围（8.64e15）会被干净地拒绝
（`{ recorded: false }`，不抛错、不变异、不留下
吞掉后续合法标记的有毒锁存）；同一验证关闭了动
作 cohort 的变体，那里坏时间戳修剪掉活状态而不
是抛错。F-22：结构化字段解析器现在按 RFC 8941
拒绝重复参数和重复字典键，表面为
`malformed_headers`。F-23：Cursor V2 的权限键改
为长度前缀（`${subject.length}:${subject}` +
`${scope.length}:${scope}`），因此被 NUL 移位的
（subject, scope）对不再能共用一个计数器。
F-24：金丝雀迷宫的淘汰只删除已过期条目；一张装
满活条目的映射会以封顶响应拒绝新 IP，而不是淘
汰一个活着的受害者并重置其计数。

**NV-1..NV-4--全部在 SDK 层确认，全部修复。**
NV-1：tripwire 在游标和停留时间到达速度流之前先
行验证--游标字段必须有限，停留时间必须有限且
在每记录 [0, 3,600,000] ms 内；无效游标被当作不
存在（不触碰 EWMA、不递增、不抛错）。NV-2：三
个令牌验证器（cursor、cursor-v2、canary-echo）在
任何解码或解析之前，把长于 **8,192 个字符**的令
牌以 `malformed` 拒绝--测得的最坏验证成本从约
3,322 ms（一个 10 MB 令牌）降到每次调用约 0.003
ms。这是本波最大的行为变化：一个签名正确但超过
上限的令牌会被拒绝，因此铸造异常长字段的主机会
拒绝自己的令牌（典型有效令牌为 140-190 个字
符；这些上限导出为 `MAX_CURSOR_TOKEN_LENGTH`、
`MAX_CURSOR_V2_TOKEN_LENGTH`、`MAX_ECHO_ID_LENGTH`）。
NV-3：Web Bot Auth 目录路径快速失败--
`parseWebBotAuthDirectory` 拒绝超过 **256 个
键**或超过 **1,048,576 个字符**的文档（真实目
录有 1-10 个键；超限输入在解析器路径上以
`key_resolution_failed` 失败关闭，或在静态
`keys:` 路径上在构造时抛 TypeError），且已解析
的目录按验证器缓存（字符串按内容 LRU 8，对象按
身份 WeakMap），把 README 记录的解析器接法从在
10,000 键目录上每次验证约 214 ms，切到首次解析
之后已解析的路径（约 0.2 ms）。NV-4：诱饵幻影
的响应写入被完全包裹--一个同步抛错、或返回拒
绝型 promise 的响应对象，不再能拒绝主机的中间
件或漏出未处理的拒绝；健康的响应行为与之前逐
字节相同。

## 第 5 部分 - 2.7.0 不声称什么

- 在 e 引擎的 mu0 界限以下永不检出（1.4）。
- SR 模式没有 Ville 保证--它的保证是 ARL，如实写
  明（1.6）。
- 没有舰队级的误标记界限--只有按 cohort 的，算术
  印出（1.4）。
- sqlite 参考存储没有跨进程公平性--只有精确性
  （2.2）。
- 政策信号没有偏转效果--只有格式（2.4）。
- ID 遍历残余或权利关卡没有移动（2.6）--并且，
  如自 2.6.0 以来一样，对业务逻辑正确性只字不
  提：错误的价格、库存竞态和 IDOR 是计量层修不
  了的主机代码缺陷。
- 经典单元数字仍是 Ledgerly/fapp 实验台上的单次运
  行实验室测量，除非写明运行次数；模拟数字恰好和
  它们的生成器一样好，这正是生成器和种子随结果一
  并发布的原因。
- 本版任何东西都没有真实流量校准。CUSUM 农场拟合
  仍受日历关卡限制（最早的诚实拟合约在
  2026-11-16，基于整整两周的农场轨迹，结论在留出
  之后）；e 引擎的保证在**真实**流量上未经证明
  （一切证据都是模拟）；C6 和 C9 的误标记率是实验
  台数字--C9 的现实世界不加载图片子群体按构造未
  测量（3.2），且 C6 的推进条件（在有声明枚举功
  能的真实主机上校准、更严格的 cohort 校准）未满
  足。C6 的合法 cohort 误标记率在实验室也偏热
  （每个家族最高 2.67-4.0%，对 1% 名义值，且只有
  200 个 TRAIN cohort）--这是一个部署条件，记录
  在 LIMITATIONS 中，不是脚注。
- 对被移植的执行层没有分布式存储测量：
  `recordIfBelow` 的原子性在捆绑的内存存储和一个
  加延迟包装的共享存储模型上验证；真实的
  Redis/SQL 规模部署未测量，从不结算响应的导出处
  理器同样未测量。
