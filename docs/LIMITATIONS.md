# Limitations and anti-claims

**This project does not make a public website “unclonable”.** If a browser can render a page, someone can capture its pixels and observe its network traffic. Client JavaScript and WebAssembly can be disassembled; Wasm is no enclave. Algorithms, data, model prompts, credentials, and authorisation decisions that must remain private belong on the server.

| Technique | What can be said | What cannot be claimed |
|---|---|---|
| No production source maps | Harder to recover original development sources from public assets | Bundle cannot be reversed; no sources exist elsewhere |
| Notice / terms | Provides provenance and published rights signals | An LLM must obey the notice |
| Canary route | Correlates suspicious access after an application is configured | Anyone hitting a decoy is malicious |
| Canary Maze | A deterministic decoy link space under a robots-Disallowed prefix; a hit is a clean investigation signal that some client followed a link no human-facing page exposes, served at near-static cost under hard per-IP and daily caps | Prevents copying or blocks REA (clients that go straight to known endpoints never follow maze links); any percentage of bots stopped or stalled (no independent measurement exists); a maze hit proves malice; poisons models or crashes clients (maze content is neutral wordlist filler by design); absolute SEO safety (safety depends on the operator correctly deploying the Disallow line, the nofollow trap link, and the built-in noindex meta) |
| `navigator.webdriver` | Weak signal for some browser automation | Detection of all Playwright, CDP or REA clients |
| Route encoding | Conceals clear strings from simple text grep | Cryptographic protection |
| AES-GCM envelope | Integrity/confidentiality against parties *without the key*, replay guard with shared storage | Hide JSON from a browser that possesses the key |
| Watermark overlay | Attribution clue if token remains visible and ledger is authentic | Reliable steganography or screenshot/video resistance |
| Zero-width/SVG markers | Byte-for-byte canary when they survive unchanged | Mathematical or legal proof of infringement |
| Client click/route heuristic | Potential anomaly data after calibration | Reliable intent classification or permission to disable paid users |
| Web Bot Auth signature (RFC 9421) | The request was signed by the holder of the published Ed25519 key for exactly the covered components, inside its validity window. `Signature-Agent` is accepted in both the draft dictionary form and the deprecated legacy bare-string form (production compatibility; the form used is reported on the verdict as `agentForm`) | The operator is trustworthy or well-behaved; identity is not authorization, and unsigned agents are not automatically abusive |
| Distinct-record budget (`createRecordBudget`) | A per-identity ceiling on how many DISTINCT records an identity receives per window, which request-count quotas cannot express; records are priced by a per-record state machine (viewed = 1, exported = 2, re-delivery free), so view and export charges never stack on the same record; enforcement is at request granularity, and the middleware's opt-in `reserveUnits` bounds parallel-burst overshoot to in-flight granularity | Stops extraction outright: the budget is per-identity, so sybil identities dilute it, and its real strength scales with the host app's account cost (free unlimited signups make it a speed bump; paid/verified/invite-only accounts make it a ceiling). Hosts with free or unverified tiers should configure those tiers with SMALL budgets (tens of records, via separate per-tier budget instances) and may lock sort/filter axes for unverified tiers, reserving bulk-shaped access for identities that cost something. Without `reserveUnits`, the default post-response accounting can still overshoot under parallel bursts - reservation bounds the overshoot, it does not make accounting transactional. Memory is bounded and partitioned - stored keys are fixed-length 16-char hashes, at most (effective limit + 1024) per identity, across at most `maxEntries` account/API-key identities plus `maxIpEntries` IP identities in a pool IP churn cannot evict from - but the default store is single-process in-memory; horizontally scaled hosts must accept per-instance budgets or supply their own shared state |
| Export scope guard (`createExportGuard`) | Removes the single-call dataset dump: exports estimated above `maxRowsPerExport` are rejected before the handler runs; with `extractRecordIds` wired, allowed exports are priced per-record through the budget's state machine (viewed rows cost the delta, re-exports are free), and 422 rejections charge a small floor so probing the guard is not a free oracle | Works without host wiring: the guard is only as good as the host's row estimate (`estimateRows` / `antireaExportRows`) - with no estimate and no `extractRecordIds` it enforces the filter floor only - the flat multiplier path (estimate only) is cruder and overcharges rows the identity already viewed, and a filter parameter's presence does not prove the export is legitimate |
| Pagination cursor (`mintCursor` / `verifyCursor`) | Integrity and binding: a cursor proves the server issued it for exactly this session and position, inside its TTL; skip-ahead, cross-session replay and stale replay fail closed with distinct reasons, and an expired-but-authentic cursor returns its decoded position so the host can re-mint and continue the chain instead of erroring the user | Confidentiality (the payload is readable by any holder - it is signed, not encrypted), or any slowdown of a client that simply follows the chain at full speed within its record budget. Binding `sessionId` to a rotating token instead of the account or a long-lived session id breaks honest chains with `session_mismatch` |
| Flow scorer (`createFlowScorer`) | Log-only telemetry over request SEQUENCES (boundary probes, signature-discriminated post-429 persistence, full-coverage pagination streaks, export bursts, canary/decoy contact) that individual legal-looking requests hide; an opt-in `onTaint` callback lets the host tighten a tainted identity's record budget | Intent classification or grounds to ban: a score is an investigation signal like a canary hit, the scorer never blocks by itself, and a patient low-and-slow agent that stays inside its record budget produces almost no signal - it complements budgets, it does not replace them. Taint is deliberately asymmetric: `onTaint` never fires for IP identities (shared NAT would punish bystanders) and never for ambient (browser-driven) decoy hits, and hosts should apply taint ceilings delayed and non-round (not an immediate, exactly-at-threshold cut) so the response does not itself become an oracle for the threshold |
| Decoy mirage (`createDecoyMirage`) | Deterministic, plausible synthetic documents on routes the real UI never calls, so probing them costs an automated caller time and tokens and produces a high-confidence flow signal; content is inert configuration-shaped data, never mixed into real responses | Proof of malice (a hit must never auto-ban by itself), or concealment: decoys CAN be unmasked by route-diffing and differential probing (comparing documents across sessions/scopes, or checking whether decoy content changes any real UI behavior) - their value is the tax on the prober and the signal, not secrecy - or any effect on a caller that only uses routes the real UI uses. Safe only under the subset it ships with: unused routes only, no shadow records in real data, mounted behind the same auth as real routes (`authorize` hook) |

No performance percentages are supplied. Any new claim requires a test, adversary model, baseline control, confidence intervals, and evidence published using [BENCHMARK_PROTOCOL](BENCHMARK_PROTOCOL.md).
