# Limitations and anti-claims

**This project does not make a public website “unclonable”.** If a browser can render a page, someone can capture its pixels and observe its network traffic. Client JavaScript and WebAssembly can be disassembled; Wasm is no enclave. Algorithms, data, model prompts, credentials, and authorisation decisions that must remain private belong on the server.

| Technique | What can be said | What cannot be claimed |
|---|---|---|
| No production source maps | Harder to recover original development sources from public assets | Bundle cannot be reversed; no sources exist elsewhere |
| Notice / terms | Provides provenance and published rights signals | An LLM must obey the notice |
| Canary route | Correlates suspicious access after an application is configured | Anyone hitting a decoy is malicious |
| Canary Maze | A deterministic decoy link space under a robots-Disallowed prefix; a hit is a clean investigation signal that some client followed a link no human-facing page exposes, served at near-static cost under hard per-IP and daily caps | Prevents copying or blocks REA (clients that go straight to known endpoints never follow maze links); any percentage of bots stopped or stalled (no independent measurement exists); a maze hit proves malice; poisons models or crashes clients (maze content is neutral wordlist filler by design); absolute SEO safety (safety depends on the operator correctly deploying the Disallow line, the nofollow trap link, and the built-in noindex meta) |
| `navigator.webdriver` | Weak signal for some browser automation | Detection of all Playwright, CDP or REA clients |
| Route encoding | Conceals clear strings from simple text grep | Cryptographic protection |
| AES-GCM envelope | Integrity/confidentiality against parties *without the key*, replay guard with shared storage | Hide JSON from a browser that possesses the key |
| Watermark overlay | Attribution clue if token remains visible and ledger is authentic | Reliable steganography or screenshot/video resistance |
| Zero-width/SVG markers | Byte-for-byte canary when they survive unchanged | Mathematical or legal proof of infringement |
| Client click/route heuristic | Potential anomaly data after calibration | Reliable intent classification or permission to disable paid users |
| Web Bot Auth signature (RFC 9421) | The request was signed by the holder of the published Ed25519 key for exactly the covered components, inside its validity window. `Signature-Agent` is accepted in both the draft dictionary form and the deprecated legacy bare-string form (production compatibility; the form used is reported on the verdict as `agentForm`) | The operator is trustworthy or well-behaved; identity is not authorization, and unsigned agents are not automatically abusive |
| Request quota guard (`createQuotaGuard`) | Per-account / API-key / IP sliding-window quotas with pagination bounds, enforced against normalized pagination the host consumes from `req.quotaPagination` (or `result.pagination`) rather than re-parsing raw query parameters — backends diverge on duplicate parameters (first vs last value), array forms, `Number()` vs `parseInt` semantics (`1e9`, `0x…`), `page` combined with `offset`, and differently cased names, so a handler that re-reads the raw query can serve a different page than the guard validated. A request with NO resolvable dimension (no account, no API key, no determinable IP — e.g. a misnamed `trustedIpHeader` behind a proxy) is counted against a single shared `unknown` bucket at the tier's normal limits by default; the legacy skip is an explicit opt-in (`allowUnresolvedIdentity`). The default in-memory stores (quota windows, Web Bot Auth nonces, envelope replay guard) fail closed at capacity: only expired entries are evicted, and a full store refuses new windows/nonces/envelopes (429 `store_capacity_exceeded` / replay rejection) instead of forgetting live accounting to make room | Quota as proof of intent, or any bound on a client that rotates identities (that dilution is the record budget's and herd detector's problem, below). The `unknown` bucket is deliberately shared: one misconfigured proxy route can make many unrelated clients share it and throttle each other — it exists so misconfiguration is loud and bounded, not invisible. A shared-store deployment inherits its store's semantics; the fail-closed guarantee is implemented and tested for the bundled in-memory stores. Window enforcement is ATOMIC (one check-and-record operation) for the bundled store and for any store implementing the optional `recordIfBelow` operation; a peek/record-only store is reported as `atomicEnforcement: false` on the guard and on every result, and its limit holds only sequentially - parallel requests against such a store can jointly overshoot, which is exactly why the flag exists |
| Distinct-record budget (`createRecordBudget`) | A per-identity ceiling on how many DISTINCT records an identity receives per window, which request-count quotas cannot express; records are priced by a per-record state machine (viewed = 1, exported = 2, re-delivery free), so view and export charges never stack on the same record; enforcement is at request granularity, and the middleware's opt-in `reserveUnits` bounds parallel-burst overshoot to in-flight granularity. The export guard's per-record middleware likewise reserves the estimate's worst-case price (2 x estimated rows) while an export is in flight and releases it at settle, and it prices non-JSON or streamed export bodies (CSV via `end`/`send`/`write`) at the flat estimate price - or a configurable floor when no estimate exists - instead of the 0 they cost before, so the parallel-burst and free-CSV holes on that path are closed; the reservation is worst-case, so an export whose worst case alone exceeds the remaining budget is refused even when its exact per-record price might have fit | Stops extraction outright: the budget is per-identity, so sybil identities dilute it, and its real strength scales with the host app's account cost (free unlimited signups make it a speed bump; paid/verified/invite-only accounts make it a ceiling). Hosts with free or unverified tiers should configure those tiers with SMALL budgets (tens of records, via separate per-tier budget instances) and may lock sort/filter axes for unverified tiers, reserving bulk-shaped access for identities that cost something. Without `reserveUnits`, the default post-response accounting can still overshoot under parallel bursts - reservation bounds the overshoot, it does not make accounting transactional. Memory is bounded and partitioned - stored keys are fixed-length 16-char hashes, at most (effective limit + 1024) per identity, across at most `maxEntries` account/API-key identities plus `maxIpEntries` IP identities in a pool IP churn cannot evict from - but the default store is single-process in-memory; horizontally scaled hosts must accept per-instance budgets or supply their own shared state |
| Export scope guard (`createExportGuard`) | Removes the single-call dataset dump: exports estimated above `maxRowsPerExport` are rejected before the handler runs; with `extractRecordIds` wired, allowed exports are priced per-record through the budget's state machine (viewed rows cost the delta, re-exports are free), and 422 rejections charge a small floor so probing the guard is not a free oracle | Works without host wiring: the guard is only as good as the host's row estimate (`estimateRows` / `antireaExportRows`) - with no estimate and no `extractRecordIds` it enforces the filter floor only - the flat multiplier path (estimate only) is cruder and overcharges rows the identity already viewed, and a filter parameter's presence does not prove the export is legitimate |
| Pagination cursor (`mintCursor` / `verifyCursor`) | Integrity and binding: a cursor proves the server issued it for exactly this session and position, inside its TTL; skip-ahead, cross-session replay and stale replay fail closed with distinct reasons, and an expired-but-authentic cursor returns its decoded position so the host can re-mint and continue the chain instead of erroring the user | Confidentiality (the payload is readable by any holder - it is signed, not encrypted), or any slowdown of a client that simply follows the chain at full speed within its record budget. Binding `sessionId` to a rotating token instead of the account or a long-lived session id breaks honest chains with `session_mismatch` |
| Canary-echo ids (`mintEchoId` / `verifyEchoId` / `resolveEchoFrom`, embedding helpers `mintEchoRecord` / `canaryEchoLink`) | Signed synthetic reference ids minted FOR one identity and embedded in that identity's own surface (list responses, record references, trap links): a different identity presenting one back is attributable evidence - the host feeds the resolved origin into the CUSUM tripwire as `CusumEvent.echoFrom` and the two identities merge into one cohort, so identity rotation stops resetting the evidence clock the moment a rotated identity touches the previous identity's surface. Measured in the 2.5.0 classic round: a rotation identity that touched the origin identity's echo id was cohort-merged at the touch (its served count at merge time: 0), and the merged cohort crossed ~1 s later at 1,392 union records with both members contributing and both step-up enrolled. Forgery resistance is the HMAC secret (server-side only) plus a 128-bit random nonce per mint, so ids are neither forgeable nor bulk-guessable from one another; verification distinguishes malformed / bad-signature / expired / scope-mismatch without echoing payload claims back | Attribution of intent: an echo touch is a correlation signal, not proof of malice - a shared or forwarded link can carry an echo id to an innocent identity, so the touch alone must never ban; it only joins the evidence ledger. Nothing about a caller that never touches foreign surface references: the echo channel is one signal among the tripwire's streams, not a detection layer by itself. The id payload (minted-for identity, scope, expiry) is integrity-protected, NOT confidential - anyone holding an id can read who it was minted for, so a host must not mint echoes for identities whose existence is itself sensitive. Echo ids expire (24 h by default) and are bound to one server secret: rotating the secret invalidates outstanding ids (they resolve as bad-signature, feeding nothing) |
| Flow scorer (`createFlowScorer`) | Log-only telemetry over request SEQUENCES (boundary probes, signature-discriminated post-429 persistence, full-coverage pagination streaks, export bursts, canary/decoy contact) that individual legal-looking requests hide; an opt-in `onTaint` callback lets the host tighten a tainted identity's record budget | Intent classification or grounds to ban: a score is an investigation signal like a canary hit, the scorer never blocks by itself, and a patient low-and-slow agent that stays inside its record budget produces almost no signal - it complements budgets, it does not replace them. Taint is deliberately asymmetric: `onTaint` never fires for IP identities (shared NAT would punish bystanders) and never for ambient (browser-driven) decoy hits, and hosts should apply taint ceilings delayed and non-round (not an immediate, exactly-at-threshold cut) so the response does not itself become an oracle for the threshold |
| Decoy mirage (`createDecoyMirage`) | Deterministic, plausible synthetic documents on routes the real UI never calls, so probing them costs an automated caller time and tokens and produces a high-confidence flow signal; content is inert configuration-shaped data, never mixed into real responses | Proof of malice (a hit must never auto-ban by itself), or concealment: decoys CAN be unmasked by route-diffing and differential probing (comparing documents across sessions/scopes, or checking whether decoy content changes any real UI behavior) - their value is the tax on the prober and the signal, not secrecy - or any effect on a caller that only uses routes the real UI uses. Safe only under the subset it ships with: unused routes only, no shadow records in real data, mounted behind the same auth as real routes (`authorize` hook) |
| Herd detection (`createHerdDetector`) | Cross-identity correlation over the served-record stream, closing the sybil dilution the record budget cannot express: two grouping mechanisms (signup chaining per IP, with a diagnostic-only global cohort view; and coverage-complement linking of complementary, co-active identities regardless of signup time or IP) scored on signup cluster, coverage ramp, tiling, contiguity, co-activity and cap pressure. Measured in the lab (scripted clients, 10,000-record target app, budget 2,000/identity): fresh-chained herd flagged at 300 combined records and capped at 600 by the ladder; staggered herd flagged at 501; distinct-IP herd reached the flaggable configuration at ~326 via the cohort view; aged-bunched herd flagged identically to fresh (300); aged-dispersed herd flagged at 2,400 by complement grouping; a dense 4-colleague same-morning onboarding team peaked at 47.2 against the 60 threshold with tiling exactly 0, and a 5-user shared-IP workday control was never flagged. Round 4 of the reconstruction study (blinded, independent attacker agents, the full stack wired from the built package against the same 10,000-record app) measured the layer end-to-end: a REA-first session's identity rotation was flagged at 1,510 combined records (score 69.99, `budget_cut_supported`) and the ladder cut the group to 100 per member — the session's own extraction from the protected instance stopped at ~15% coverage, closing round 3's free-account sybil escape for that shape | Flags herds that are BOTH signup-dispersed AND slice-interleaved: that shape groups under complement linking but peaks at score 57.3 of 60 (interleaving collapses the contiguity term) - it is asserted as an open limit in `tests/herd-detector.test.cjs`, not claimed as covered. Round 4 measured the enforcement ceiling as plainly as the success: an adaptive session rotating 18 identities, whose broad exploratory overlap kept group tiling below the band gate, was flagged twice (at 1,311 and at 5,999 combined records) but both flags landed `graduated_only`, the ladder refused the cuts by design, and the session extracted the full dataset in 272 requests. Low-tiling herds are therefore DETECTED, and - under the 09:44 default law - taxed at the friction tier by the library's default band response (step-up + soft budget step-down), but not stopped by this library; stopping them needs host-side escalation beyond friction attached to the flag. Micro-slice herds (under ~150 records per identity, pairwise unions never reach the link floor; covering a dataset then needs dozens of identities) and shift-work herds (identities never co-active inside the link window) are likewise open: their counter is identity cost, not correlation. Since 2.5.0 the complement grouping is leader-based - an identity's coverage group is compared against other groups' aggregates (refcount map + block bitmap), with NO per-pair state - and a flagged group re-announces itself (supplementary flag, coalesced at one per 5 s per group) when a late joiner or a pending partial contributor crosses the materiality floor (25 unique records at the shipped defaults), closing the measured hole where a flag only ever consequenced the members present and material at first crossing (the slicing herd's grouping went from 8 of 18 phase-1 identities to all 18 in the 2.5.0 classic round). One announced state is a deliberate contract, not an oversight: a member announced at exactly zero unique coverage is settled-inactive and never re-triggers a supplementary on its own - re-firing for it would break the once-per-window discipline quiet groups rely on; if it later becomes material, the NEXT member's crossing (or the next window) announces the group with its coverage included in the snapshot. Measured scale (same bench harness both versions, scripted event streams, this machine): the pre-2.5.0 pairwise grouping needed 131.3 s for a 1,000-identity × 60-record stream (21.9 ms/event) and 0.81 s at 500 identities; the leader grouping processes the same 1,000-identity stream in 1.55 s, a merging 500-identity × 200-record stream (one coverage group of 500) in 2.73 s, and a 2,000-identity × 60-record stream in 6.2 s - beyond a few thousand concurrent identities the remaining per-event cost is the v1 feature computation over group members, and the honest bound is the `maxIdentities` cap (2,000 by default) rather than the grouping itself. All lab clients were scripted and deterministic: the flag points prove the mechanics against those scripted shapes, not detection rates against adaptive agents. The cohort view never flags (its real-world false-positive risk at genuine signup volume is unmeasurable in a lab), and a flag is an investigation signal like a canary hit, never proof of malice by itself |
| Herd response ladder (`applyHerdLadder`) | Converts a herd flag into a group-level ceiling by lowering each member's record budget via `setOverride` - but ONLY for the herd partition profile: every flag snapshot carries a response band, `budget_cut_supported` when the group's tiling is at/above the configured cut threshold (measured herds tile ~1.0), and the ladder refuses any other band in code, returning `reason: "graduated_only"` with no override applied | A budget cut for low-tiling flags: the one measured legitimate group that crossed the threshold - a compliance team systematically reviewing a full segment (uniform coverage by job description) - flagged at 60.008 with tiling 0.239 and would have been cut near the end of legitimate work. Low-tiling flags support graduated response only (step-up verification, export-only restriction, human review). Since the 09:44 default law, the shipped default response to a flag (`defaultHerdBandResponse` in `enforcement-tiering.ts`) IS that graduated response at the friction tier - step-up plus a soft budget step-down to the 500-record floor - for inferred cohorts on both bands; the ladder's deep cut engages only for host-declared cohorts or ceiling-tier calibrated evidence. Since 2.5.0 the friction-tier response is targeted by contribution: flag snapshots carry per-member coverage, and `herdFrictionTargets()` keeps only members whose unique coverage is material (>= 25 records by default) - measured in the 2.5.0 classic round, the polite user and all 5 NAT users inside a flagged combined group were skipped (unique coverage 0) while friction landed exactly on the systematic-review seats. The band is a policy floor, not a guarantee: a herd that deliberately overlaps its slices to depress tiling trades extraction efficiency for a graduated response, and hosts remain responsible for the consequence they attach to either band. Round 4 of the reconstruction study exercised both branches against live attacker agents: the ladder cut a high-tiling REA-first rotation at 1,510 combined records (that session's extraction stopped at ~15%), and refused two low-tiling flags from an adaptive 18-identity session, which then extracted the full dataset in 272 requests — the refusal discipline and its price are both measured, not hypothetical |
| Transactional disclosure ledger (`createDisclosureLedger`) | A cohort-wide shared ceiling over the EXACT union of served records, enforced at one atomic point (`reserveDisclosure`): parallel reservations provably cannot jointly overspend the ceiling when the backing store implements the `transactLedger` CAS contract - the shipped conformance test reserves exactly the ceiling (100 records) across 40 parallel reservations against a deliberately slow in-memory store, and refuses the rest. Reservations count against the ceiling while open and are bounded (TTL, per-subject outstanding/reserved caps, idempotency keys), and evidence accumulators live in the same transaction, so a version conflict retries the whole decision, never half of it. Idempotency keys are bound to the exact request that first used them (subject + record ids/count for the ledger; subject + action + cost + cohort for `createActionBudget`): a replay with a different subject or payload is refused `idempotency_conflict`, so keys MUST be host-generated and unguessable - a guessed key can no longer ride on another subject's reservation. Store failures fail closed everywhere in this layer: corrupt or wrong-shaped stored state, CAS exhaustion and a throwing store all surface as structured `store_conflict` refusals (and `store_unavailable` 429s from the quota guard), never as exceptions escaping into the host | Any enforcement claim over a store without a transaction primitive: get/put stores run in a declared `audit_only` mode (`enforced: false` on every decision) where the ceiling is computed best-effort and CAN be overspent by concurrent writers - the SDK reports this instead of hiding it, and hosts that need the guarantee must supply a transactional store. The bundled in-memory store's CAS is per-process (a promise-chain mutex): it is not a distributed lock, and horizontally scaled hosts must adapt their own atomic store (SQL transaction, Redis Lua) to the same contract. Bucket pacing refuses whole reservations with a `retryAfterMs` rather than serving partial pages, so a rate-limited cohort sees refusals, not trickle service |
| Campaign ceiling registry completeness | With a declared registry, unregistered subjects fail closed by default, and `checkRegistryCompleteness` reports members the host expected but never registered - the product form of the lab round-6 finding that a partial registry silently degraded a campaign guard to per-member protection while 17 unregistered identities extracted 9,293 records | Protection for cohorts the host never declares at all: an undeclared rotation is invisible to the ledger until detection links it, and a host that declares a registry but never reconciles it against its own account list still owns the gap. The `audit_only` unregistered policy is an explicit opt-out that reopens the hole in exchange for a flag on each affected decision |
| CUSUM tripwire (`createCusumTripwire`) | A sequential evidence accumulator whose form removes the fixed-threshold surfing strategy: four streams (predicate adjacency, exact-set tiling, cold-ID misses, cursor velocity) sum into one one-sided accumulator with a zero floor, so an attacker cannot bank innocence below zero or sit at 85% of several independent thresholds at once. Lab-fitted tables (r6-calib-1) at the lab's alpha reproduced the round-6 calibration predictions - compliance seats cross evidence thresholds solo yet are never restricted BEYOND the friction tier by the engine (gates are written against restrictions, not flags), host-declared protected seats are never restricted at all, and the engine's tiering clamp caps its own enforce-mode consequence at step-up friction whenever the tables are uncalibrated. The shipped default mode is `enforce` at that step-up tier (the 09:44 default law), still gated by the consequence floor below. A consequence floor gates every consequence behind absolute scale: below 150 exact union records by default (the tiling stream's per-member evaluation gate, reused as the floor constant; host-configurable via `consequences.minUnionRecords`) a crossing is telemetry only - the v24 classic test's polite+NAT cohort crossed at a union of 25 records and, after the fix, accrues the flag with zero friction, while a campaign-scale crossing (union 700 in the same test) still enrolls step-up | Calibrated detection rates on real traffic: the bundled tables were fitted on SCRIPTED lab traces only (fitted N_eff = 189, against Argon's asserted-but-never-fitted 4,000), the tiling stream was INERT in that fitting harness (no legit component reached its evaluation gates, so its increments rest on thinner evidence than the other streams'), and snapshots carry `uncalibrated: true` plus the notice "uncalibrated - audit only". Cohort formation for the two blind shapes shipped in 2.5.0: served-set complementarity links filtered-list slicers (a text filter has no honest range predicate, but the exact served set is always known) and cold-walk complementarity links detail-channel walkers whose cold fetches tile disjoint, range-dense ID ranges - measured in the 2.5.0 classic round as first crossings at union 1,700 (slicing) and 900 (ID walk), where the 2.4.0 round had zero crossings on both shapes. What remains open: a SOLO walker never forms a cohort (formation needs a complementary partner), and attackers staggered beyond the co-activity window evade formation entirely (the calibration fit's dispersed family: 0 of 6 traces detected by either table set). The systematic-review shape still forms and crosses identically to a walker team - the signals do not separate them, and the mitigation is the tiering law (friction cap for inferred cohorts) plus the protected-cohort declaration, not the signal. Friction now targets contributors only (`consequenceTargets` / `herdFrictionTargets` over per-member coverage), and the 2.5.0 classic round measured the previously unmeasured case: polite users browsing mid-session inside a flagged group received zero consequences (0 enrollments, 0 dwell, 0 session expiries, 0 step-downs). Residual adjacency/tiling correlation after the conditional exclusion is unquantified, so the nominal alpha is not claimed to hold. State is in-process memory in this version (no host EvidenceStore adapter yet), so flags are per-process signals on scaled deployments; identity state is capped (`maxIdentities`, default 2,000, least-recently-active eviction - host-declared members are evicted last) and snapshots report live `stateSizes`. Epoch rotation retires the score and the per-member contributions with the flag - a new epoch starts from zero evidence, so stale contributors are no longer friction targets - while served/union coverage (a fact the consequence floor reads) is kept. A throwing `onCampaignFlag` no longer loses a flag: delivery stays pending and is retried on the cohort's next observe/snapshot, and throwing `isProtected`/`isExempt` predicates are treated as absent predicates rather than escaping into the host's request path. `checkServe` refuses non-finite or negative request sizes structurally (`invalid_request`) instead of letting them reach the pacing bucket, and `clearCohort` also resets that bucket, so a damaged bucket has a recovery path. Consequence eligibility is evaluated live on every decision, snapshot and `checkServe` call, but `onCampaignFlag` fires once at the crossing itself: a cohort that crosses below the floor and later grows into eligibility does not re-fire the callback, so push-style hosts must poll snapshots to notice the transition (`checkServe` applies the floor on every call regardless). The noise floor is a proxy fitted from scripted controls (~45 novel records/user-hour; full extraction at that floor ~120-170 h centrally), NOT a population measurement. A population false-friction rate under the enforce-by-default law: an UNDECLARED legitimate team doing systematic full-coverage review can now eat friction (step-up re-authentication cadence, bucket pacing, soft budget step-down) - that residual risk is accepted by the new default and is mitigated by the consequence floor and the protected-cohort declaration, but how often it fires on real traffic (how often a real user is made to re-authenticate) is unmeasured; no percentage is claimed |
| Declared campaign ceiling, end-to-end (2.5.0 classic cell) | The lawful hard-ceiling path - host-declared cohort + ceiling-tier calibration manifest + `checkServe` wired into the serving path - is ARMED AT DECLARATION: declared groups form one cohort at tripwire construction, snapshots/decisions report `ceilingArmed` / `ceilingActive` from first sight, the union counts from the first record, and `checkServe` enforces the cap with no crossing and no consequence floor, capping multi-record requests at the remaining headroom. Re-tested end-to-end in the 2.5.0 ceiling-fix round (two runs on the final build, persistent ID-walk driver, sequential wiring): the 18 declared identities stopped at EXACTLY 600 distinct records in both runs (the crossing-gated first attempt in this same cell overshot to 2,700), every walker blocked, 710-714 `campaign_ceiling` refusals per run with 0 records served past the cap, and controls in the same instance were unaffected (declared-protected compliance 1,200/1,200, zero friction; a separate protected-registry cell re-ran 1,200/1,200 with zero friction, proving the registry is not the declared cohort). A declared cohort WITHOUT a ceiling-tier manifest arms nothing, and inferred cohorts keep the crossing-gated engagement unchanged | Exactness under concurrency the lab did not exercise: `checkServe` is a check, not an atomic reservation - two concurrent serves that both pass the check below the cap can jointly overshoot it by their in-flight requests, the same check-then-serve gap the disclosure ledger's transactional `reserveDisclosure` exists to close; the exact-600 result is proven for the sequential single-process wiring measured here. Only one declared size (600) and one attacker shape (persistent sequential ID walk, detail channel, 1 record per request) were measured; list/export surfaces serving many records per request are covered at SDK level by the headroom cap (unit-tested) but were not classic-tested against an armed cohort. Arming is evaluated when the cohort is declared/first seen: a manifest that expires mid-process does not disarm an already-armed cohort in this version (the declaration is treated as the host's standing decision; revocation is `clearCohort` plus removing the declaration). Declared cohorts of one member are armed and capped, but their evidence score still cannot cross (scoring requires a pair) - the cap does not need the score |
| Enforcement tiering (`clampEnforcement`) | Converts the R5 compliance lesson into a checkable rule with the 09:44 default: behavior-inferred cohorts receive friction BY DEFAULT (step-up plus a soft budget step-down via `softBudgetStepDown` that may lower a budget but never below the 500-record floor `SOFT_BUDGET_FLOOR_RECORDS`, derived from the disclosure ledger's per-subject reservation bound), and no code path in this package can apply a hard ceiling, a below-floor budget cut or cold pricing to a behavior-inferred cohort on uncalibrated evidence, even when configuration demands it - the clamp is a pure function hosts can also call before attaching their own consequences, `defaultHerdBandResponse` ships the default herd-flag response under the same law, and `validateHerdResponseConfig` makes the specific R5 wiring mistake (pricing the herd `graduated_only` band) a startup configuration error |
| Protected cohorts (`createProtectedCohortRegistry`) | A host-declared, auditable protection lane for the subjects inference must never consequence - compliance reviewers, audit teams, support accounts, agreed pentest windows: protected subjects accrue full telemetry (their events still form cohorts and flags, snapshots list them under `protectedMembers`) while receiving zero consequences from INFERRED evidence (no step-up, no budget step-down, no CUSUM pacing), via the tripwire's `isProtected` predicate and the registry's `guardInferredConsequence` / `partitionConsequenceTargets` host-side gates; declarations record a reason and may carry an expiry after which protection lapses on its own | Immunity from consequences the host itself authorized (a host-declared cohort's ceiling is the host's own decision and ignores the registry), or from direct per-subject evidence: a protected subject's own programmatic decoy hit still taints that subject, because a declaration must not become a laundering lane. Nor does the registry fix false positives for teams the host never declares - an undeclared systematic-review team remains exposed to the default friction tier (see the CUSUM row), and declaring sloppily (e.g. protecting a whole user tier) re-opens the extraction lane the friction tier exists to tax | A guarantee about host code the SDK cannot see: a host can ignore the clamp, wire its own pricing to any signal, or declare cohorts carelessly - host-declared cohorts may be hard-ceilinged precisely because the host owns that authorization decision, and a host that declares cohorts from the same inferred signals re-creates the R5 failure under a declared label. The tiering law bounds what THIS library does with inferred evidence; it cannot bound what an operator does with the same raw signals outside the library |
| Calibration manifests (`evaluateCalibrationManifest`) | Calibration quality becomes an auditable, named, expiring artifact (model version, sample sizes, held-out FP/FN, method, attester) with tiered consequences, replacing a boolean gate anyone could flip; a malformed or expired manifest can only weaken enforcement (evaluation never throws, every defect is named). Since 2.5.0 the repo also ships an offline fit script (`scripts/fit-cusum-calibration.cjs`) that produces a lab-simulated opt-in table set (`r7-labfit-1`) and a sample manifest from held-out trace numbers; that manifest evaluates to the step_down tier only, and the SDK default remains the r6 tables because the fitted set did not beat them on both holdout sides | Proof that a manifest is TRUE: a host can fabricate sample sizes and error rates, and evaluation cannot detect it - the manifest makes fabrication a signed claim an operator can be challenged on, not an impossibility. The ceiling-tier floors (FP <= 0.01, FN <= 0.50, sample minimums) are policy defaults, not derived constants; hosts with different risk postures must set their own and own the choice |
| Cursor V2 (`mintCursorV2` / `verifyCursorV2`) | Rollback resistance V1 cannot offer: because verification compares the token's `ledgerVersion` and chain sequence against the store's current authority and the store wins unconditionally, replaying an older authentic token (or presenting one from ahead of the store) fails closed with distinct reasons, and the payload provably carries no evidence state (the key allowlist is enforced on presented tokens, not just on minting) | Stateless pagination: V2 requires a store read per verification, and a store outage fails new disclosure closed rather than degrading to token-only truth - hosts that cannot accept that dependency should stay on V1, whose session chaining is unchanged. Like V1, the payload is integrity-protected, not encrypted, and V2 does not slow a client that follows the current chain at full speed within its budget |
| Evidence attribution (`createEvidenceAttributor`) | Bounds evidence poisoning at the attribution layer: an actor cannot manufacture enforcement credit against another subject - cross-contribution requires a host-declared relationship and is capped per pair and decayed, inferred links earn observation only, and unknown links are quarantined to audit with zero credit, so framing a cohort-mate costs the attacker its own full attribution first | A solution to insider poisoning inside a host-declared cohort: a declared member framing its own cohort remains a host trust-boundary problem (the R8 review's accepted residual); the pair cap and decay bound the blast radius and the audit log preserves the attempt, but deciding that a declared relationship was abused is the host's call |

| Canary actions (`createCanaryActionRegistry`) | Direct per-subject evidence for features: the host registers target keys no legitimate UI ever emits (a never-linked export slice, a never-shown promo id), and a touch taints ONLY the touching subject - taints never splash onto other subjects, attribution comes from the authenticated subject on the request so a canary target cannot frame another subject, and a protected subject's own hit still taints that subject (a declaration is not a laundering lane). | Clock discipline (L-DEEP-2) | Every INTERVAL the SDK measures in-process - quota and record-budget windows, flow-scorer session idle, herd co-activity / link gates / flag re-arm / supplementary cooldown, action-cohort window pruning, taint lifetime and supplementary cooldowns, evidence cross-credit decay, the Canary Maze per-IP window, the replay guard's nonce TTL, the CUSUM cohort pacing bucket's refill, and the browser behavior shield's per-minute rates - is computed on a monotonic clock (`performance.now()`, anchored to epoch scale), so an NTP step, a VM suspend/resume or a manual clock change can neither reset a window early nor stretch it past its design. The regression suite (`tests/mono-clock.test.cjs`) replays the lab harness scenarios against the shipped modules: a +5 min step no longer reopens a spent 60 s window, and a -5 min step no longer blocks a legitimate identity for an extra 300 s. Hosts may inject the interval clock per module (`monoNow` option); a host that injects only the existing `now` clock keeps the pre-patch single-clock behavior exactly. The two persisted ledgers (`createDisclosureLedger`, `createActionBudget`) are hybrid by design: bucket refills never credit more elapsed time than a bucket needs to fill, and a reservation - or a subject/cohort window - created or rolled BY THIS PROCESS also expires/rolls at its monotonic TTL/length, whichever of the wall deadline and the monotonic deadline comes first | Anything cross-process about time: persisted ledger/budget state carries wall-clock deadlines only, so a reservation or window RESTORED from a store, or written by ANOTHER process, has no monotonic mirror and follows the wall clock alone until this process creates or rolls its own (the monotonic mirrors are process-local maps, never persisted or shared). Calendar semantics stay wall-clock by design: the Canary Maze daily cap is a UTC-day rule, the CUSUM epoch rotation and herd/action formation windows run over host-supplied event timestamps, and expiry/deadline fields in snapshots and stored state remain wall time for hosts to compare. The monotonic anchor is a scale convenience only - `performance.now()` resolution and suspend behavior are the platform's, and no claim is made about intervals spanning a process restart |
