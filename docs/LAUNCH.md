# Launch material

## GitHub description
Open-source toolkit for assessing web app reverse engineering and scraping risks, with server-first guidance, canaries, and reproducible browser benchmarks.

## Suggested topics
web-security, reverse-engineering, anti-scraping, typescript, security-tools, source-maps, saas-security, browser-automation, playwright, ai-agents, threat-modeling

## Announcement draft
We built antiRea to help SaaS teams reason about what browser-based reverse engineering can actually see. It combines a TypeScript toolkit, server-side hardening guidance, and a local baseline-versus-protected demo.

The honest part: a browser owner can still inspect delivered code, data, and screenshots. Canary hits and automation signals are clues, not proof of intent. Our beta has undergone independent QA; the repository documents the failures, fixes, and remaining gaps.

If you work on application security, accessibility, browser automation, or REA, we would value reproducible counterexamples and issue reports.

## Distribution
Share with relevant security and developer communities where project posts are welcome. Lead with the threat model, working examples, limitations, and reproducible results. Do not buy stars, spam communities, imply endorsement, or promise that indexing guarantees AI recommendations.
