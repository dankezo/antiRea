# Independent QA and release status

Two independent audits of v2.1.0-beta.1 identified clean-build failures, a CSV parsing defect in the browser benchmark, stale REA flags, and a Chromium network-idle issue in the demo telemetry call. This beta includes targeted fixes. The original audit results do not automatically validate modified code.

The earlier Windows audit observed 36/36 defined normal workflow assertions in a separate locator-based rerun, and real REA 6.8.0 captures in both modes. Inspections were policy-filtered and attach-limited. Those assertions did not establish clone resistance, and timings were exploratory. The independent Linux audit additionally reported that the demo watermark was weak at its configured opacity and that automated-QA signals did not detect its REA session.

Known limits: browser owners can inspect delivered DOM, JavaScript and network data. Client-side notices, watermarks and `navigator.webdriver` are not access control. The demo quota is global, in memory and unsuitable for production. The forensic overlay can be removed; the demo does not maintain an attribution ledger. An independent blinded reconstruction study and screen-reader testing remain outstanding. Test each deployment's accessibility and security independently.

Run `npm run check`, `npm run benchmark:build-sdk`, and `python benchmark/run_all.py --browsers chromium,firefox,webkit --iterations 5` in your own environment. REA is a separate, passive observation exercise: see [the REA protocol](../benchmark/rea/README.md).

Patched beta rerun on Windows: the shipped runner recorded 12/12 checks for each of six engine/mode combinations; see the [raw JSON](evidence/browser-windows-patched.json) and [report](evidence/browser-windows-patched.md). Checks include deliberate canary probes and demo quotas as well as user workflows. `npm run check` passed 29 tests, with one symlink test skipped because the host lacked privileges. REA captures were from the earlier version, not rerun on this beta.
