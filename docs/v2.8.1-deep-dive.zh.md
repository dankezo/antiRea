# antiRea v2.8.1 深入解析

> 一个补丁版本，只有一处修复：为两个相位信号加 span 门。这个问题在 2.8.0 发布当天就在本项目自己的测试 range 上实时暴露；下文一切都是 range 记录、回归测试文件与套件记录，没有任何数字是真实流量测量。

## 第 1 部分 - 本次发布内容

没有新模块。只在两个既有信号 `createHerdPhaseSignal` 与 `createActivityPhaseSignal`（后者继承 herd-phase 核心）中改了一处行为，并新增一个结果字段 `spanEligibleMembers`。没有任何既有测试预期被修改。

套件：817 个测试（815 个通过，0 个失败，2 个既有的 RSA-PSS 跳过），比 2.8.0 的 812 个增加 - 新增的 5 个回归测试在 `tests/phase-span-gate.test.cjs` 中，既有预期零改动。

## 第 2 部分 - 问题：纯几何造成的相位锁定

两个信号都从调度器网格（周期 `periodSec`，默认 900 秒，也是唯一经过实验室验证的周期）上的事件相位读取协调性。每个事件映射为圆上的一个相位；成员的 R_i 衡量其自身相位的集中程度，R_cohort 衡量队列平均向量的集中程度。

在一个周期的一小部分内，任何群体的所有事件都落进圆上的一段小弧内。于是无论该群体是否由调度器驱动，集中度都接近最大值，R_i 与 R_cohort 仅因几何原因就趋近于 1，一个只被短暂观察的群体便可能被确认为协调的 herd。

这正是 2026-11-09 antirea-range 冒烟运行出现的情况：12 名合法读者，在 40 秒窗口内被观察，以 R_cohort 1.0000 被确认。

## 第 3 部分 - 门的规则

现在，确认还额外要求该成员被观察到的事件跨度至少覆盖一个完整的网格周期：`lastSeen - firstSeen >= periodSec`（默认 900 秒）。只有满足 span 条件的成员才计入确认，也只有他们才可能被点名。

- 描述性统计不变：`memberCount` 与 `cohortR` 仍对所有被评分成员计算，仪表盘上仍能看到原始几何形态。
- 结果在 `memberCount` 旁新增 `spanEligibleMembers` 字段，宿主可以看出队列是被这道门挡住，而不是被统计量挡住。
- activity-phase 信号从共享核心继承同一道门和同一字段，没有单独的规则。
- 实验室各格不受影响：它们的跨度覆盖许多周期，套件重新验证后既有预期零改动。这道门拒绝的不是某种行为模式，它拒绝在短到不具含义的证据上做出确认。

## 第 4 部分 - 回归覆盖与发布门

`tests/phase-span-gate.test.cjs` 固定了五格：

- (a) 短跨度合法群体 - 不被确认（即 range 上的那个案例）；
- (b) 带 jitter 的长跨度合法群体 - 如从前一样不被确认；
- (c) 长跨度对齐 herd - 仍被确认（正面对照：这道门不会削弱真实信号）；
- (d) 混合跨度 - 只有满足 span 条件的成员被计入并被点名；
- (e) herd-phase 核心本身带有这道门，不只是 activity 包装层。

该修复还通过了强制性的 range 发布门（`antirea-range/gate.cjs`：SDK 套件 + 冻结的误报/检出格 + range 实时冒烟），6/6 PASS。
