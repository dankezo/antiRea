# antiRea v2.9.1 - 深入解析

> 七项服务器端能力补充了计量、证据与宿主响应之间的空白。本文在 2.9.2 审计期间完成，区分实际重跑的端口一致性与缺少生成器的历史结果。下列数字均不是生产检测率。

## 第 1 部分 - 发布内容

新增 `createOwnershipProbe`、`createOccupancyEarlyMinimalSignal`、`createStepUp402Responder`（含 `manifestDocument`、`checkAssertion`）、`createDeclarationLog`（含 `importDeclarationLog`）、`applyVolumeRankRule`、`selectEmpMixThreshold`，以及 `computeHoldTypeFeatures`、`createHoldTypeScorer`。信号仅提供建议；宿主提供认证身份并决定后果。校准工具是纯计算，不是新的授权机制。

本文记录 2.9.1 的设计。后续修复也涉及旧模块，因此另有 [2.9.2 解析](v2.9.2-deep-dive.zh.md)。最终测试数量与重复性能测量见[审计记录](audit-2.9.2.json)，不沿用旧公告的数字。

## 第 2 部分 - 要解决的问题

记录上限衡量数量，却不知道对象属于谁。零活动占座检测会漏掉发出少量活动的占座者。没有结构的挑战无法为合作机器提供下一步。偏好声明可能在数据转载时消失，而值水印本身无法说明声明何时存在。

其他新增项把实验室 runner 中的小计算暴露为 API。它们不会拟合真实生产群体，不会可靠地分配 persona，也不会把合成数据分离自动转成运行阈值。

## 第 3 部分 - 工作机制

- **所有权观察：** 在滑动窗口计数访问和不同所有者；公共路由排除，未知所有者只计入分母。合法客服队列也可能呈现扫描形状。
- **早期最小活动占座：** 统计新账户持有、只有一到两次且全部发生于早期的活动会话，占房间容量的比例。它补充零活动信号，只输出房间状态，不指控在座者。
- **402 响应：** HTTP 与 manifest 包含支付、申诉、免费继续。宿主必须先触发 step-up；没有结算服务，不合作调用者可以忽略它。
- **声明日志：** 宿主维护的哈希链证明给定历史的内部完整性，不证明爬虫遵守、外部时间认证或法律效力。
- **按量排名：** 按 EB05 降序排列全部单元格；至少两项稀有格进入前 5% 才标记。同分保持输入顺序。分数和稀有性由宿主提供。
- **EMP-MIX：** 合并 FMR 样本，选择最大的合格网格点。两组样本数量相等时恢复登记的 50/50；不等数量是另一种混合，未由原登记验证。
- **Hold-type：** 根据宿主人类参考群体计算会话时间特征和有符号标准化分数。特征分离不等于检测器，也不等于真人认证。

## 第 4 部分 - 审计实际复现了什么

在 Windows x64、Node v24.19.0 上，原 RECOMB-04 算法重现冻结 JSON，只有计时元数据不同。SDK 的 4,480 项逐身份比较全部一致；MID 检出复现 0.90 / 0.85 / 0.85。关键更正是分层：实验室合法身份使用生成器成分标签，SDK 使用观测总量。kappa 1000 的一个误报原属 147 个 MID 身份；按 SDK 重分组后属 115 个 HIGH 身份。因此实验室打印的最大值 0.007 不能当作 SDK 重分组的 0.008696。

EMP 算术复现全部 65 个已存网格点，各污染水平均选 0.36。缺少 `r14-lab/common.cjs`，不能重新生成完整群体。舍入表格与原 JSON 精度不同，不是算术缺陷。

原 RECOMB-09 runner 已完成；1,000 个 SDK 响应在 JSON 序列化后与原文提取的 `shape402` 逐字节一致。合作调用者的退出 189/200、assertion 188/200 得以复现，但不支持对忽略响应者的效果声明。Hold-type 在 90 个已存会话上复现 450 个特征值、270 个分数，数值差为零。

D2 在 25 个独立 fixture、5,925 个 tick 上与提取的因果序列一致。这不等于登记种子回放：缺少房间生成器，历史触发时间和 lurker 峰值在本次仍为 NOT VERIFIED。缺少 `harness-v2/index.cjs`，也无法完整重跑 RECOMB-10 群体。[证据摘要](evidence/audit-2.9.2-summary.md)列出命令与缺失输入。

## 第 5 部分 - 有意的映射差异

声明实验室对整个声明块计算哈希；SDK 对每项 form/declaration 计算哈希，不承诺逐项 digest 相同。原 probe 判断最后一项声明是否早于副本；公开 `predates` 判断最早声明是否不晚于给定时点。两者在原来的历史结束后向量上一致，在历史内部可以不同。保留公开合同并说明映射，比修改一方制造哈希相同更诚实。

分层与舍入也遵循同一原则：逐身份标记可以一致，标签和打印精度却不同。审计明确记录这些差异。

## 第 6 部分 - 限制与 2.9.2 后续

所有者、公共路由、会话身份和账户创建时间都由宿主信任边界决定。合成群体不能验证生产 FP。D2 仍有较弱 lurker 余量以及延迟活动、额外活动盲点。有效哈希链前缀不能证明尾部从未被删除；需要独立锚定数量与头哈希。

本次发现的资源、恶意输入和 Unicode 缺陷涉及新旧模块，另见 [2.9.2](v2.9.2-deep-dive.zh.md) 与 [LIMITATIONS](LIMITATIONS.md)。未重新生成的历史结果仍明确标为历史结果。
