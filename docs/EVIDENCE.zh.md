## 2.9.3

补丁补充：Linux x64、Node 24.22.1，运行于维护者的 Linux 虚拟机。测试 974/972/0/2；完整发布门 PASS 11/11（SDK 测试集、两个冻结 FP 单元格、一个检测单元格、新增 Gate 2.5 黄金等价校验及其种子突变自证、以及真实 range 冒烟测试）。两个实验室项目在运行前按冻结注册测量；一个已发布，另一个被其自身的门淘汰，并按下文记录为淘汰。

**影子诱饵图（BLA-02）。** 冻结实验室注册，种子族 20301xxx（区块 20301201-20301212），两次运行逐字节相同。数据：2,000 条合成真实记录（50 位作者、链式系列），12 个种子实例中每个分支 60 个诱饵。一个不动点引用完整性攻击者（引用解析、计数一致、链对称、时间戳单调）移除了 100% 的孤立诱饵（合计 720/720）和 0% 的影子诱饵（0/720）；无诱饵对照组在 24,000 条真实记录中损失 0 条，放置审计从任何合法入口到达 0 个影子节点。范围：真实图是规则的合成生成器，未运行真实 REA 遍历器，且未测量抗统计指纹识别--影子生成器不以真实图为输入，因此按结构不会泄露共享模式之外的任何信息，其分布有意与真实图不同。结论：**PASS-lab**，以 `generateShadowDecoyGraph` / `verifyShadowGraphClosure` 发布。

**token 签发时间合规（LPG-07）。** 对已发布 2.9.2 验证函数的确定性探针（固定时钟、无种子）：`verifyCursor`、`verifyCursorV2` 与 `verifyEchoId` 均接受 `iat` 在未来一小时的正确签名 token，并忽略非数字 `iat`。修复后，同一探针在超出 60 秒偏差时返回 `not_yet_valid`，对非数字 `iat` 返回 `malformed`，正常、偏差内与过期对照均未改变；step-up 证明与 Web Bot Auth 验证函数本来就拒绝未来签发，未作改动。同一轮发现的相邻缺口：Web Bot Auth 的 `verify()` 对 null 请求抛出 TypeError；现在返回结构化的 `no_signature_headers` 结论（SLC-05）。

**参数抖动（IA-02）--已评估，不构建。** 冻结注册，种子族 20301xxx（区块 20301101-20301112），通过已发布的 `createRecordBudget` 测量，有效预算从 [130, 170] 均匀抽取，公开默认值为 150。检测门通过：按公开默认值调校的攻击者在 12 个部署中的 5 个被拦下（41.67%，冻结下限 35%），抽取值为 150 及以上时误拦 0 次，12/12 次周期轮换改变了抽取值。误报门未通过：在 IA-01 语料的 253 个合法身份窗口上，12 次抽取中有 4 次新拦截比例超过冻结的 1% 上限（抽取 132：5.138%；134：4.743%；137：4.348%；146：1.581%；平均 1.383%）。每个被新拦截的身份都是需求高于 130 条记录的合法高级用户；从未有普通用户被新拦截--但比例条款仍然是约束性的。结论：**KILL**，按淘汰记录，不作软化；不同的区间将是一次新注册。

**方法。** 我们在 **Ledgerly** 上测试：这是一个合成 SaaS，在 120 个账号之后存放着 10,000 条记录，运行两次：一个没有保护的 baseline 实例，以及*同一个*应用接入 antiRea 的 protected 实例。攻击运行由 REA 6.8.0（`rea-agents`）和遵循标准克隆流程的通用智能体驱动：认证、枚举、探测边界、分页直至完全覆盖、批量导出。（一个发现决定了下文的一切：REA 本身只*感知*--它通过 CDP 读取正在运行的浏览器，自身发出零个请求。服务器能观察、计量和定价的是背后的驱动流程，因此防御针对的正是它。）礼貌用户对照运行用来测量对合法流量的代价。关于本仓库的一份独立基准测试也已发表在 [issue #1](https://github.com/dankezo/antiRea/issues/1) 中；其中大多数主张都经受住了检验，它发现的差距也已修复并记录在变更日志中。
