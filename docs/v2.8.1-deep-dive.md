# antiRea v2.8.1 - deep dive

> A patch release with one fix: a span gate for the two phase signals. Found live on the project's own test range on the day 2.8.0 shipped; everything below is the range record, the regression file and the suite record - no number here is a real-traffic measurement.

## Part 1 - What shipped

No new modules. One behaviour change in two existing signals, `createHerdPhaseSignal` and `createActivityPhaseSignal` (the second inherits the herd-phase core), plus one added result field, `spanEligibleMembers`. No pre-existing test expectation changed.

Suite: 817 tests (815 pass, 0 fail, 2 pre-existing RSA-PSS skips), up from 812 in 2.8.0 - 5 new regression tests in `tests/phase-span-gate.test.cjs`, zero pre-existing expectations changed.

## Part 2 - The problem: phase-lock by geometry

Both signals read coordination from event phases on a scheduler grid (period `periodSec`, default 900 s - the only lab-validated period). Each event maps to a phase on the circle; a member's R_i measures how concentrated its own phases are, and R_cohort measures the concentration of the cohort's mean vectors.

Inside a fraction of one period, every event of every population lands inside one small arc of the circle. Concentration is then near maximal for any population at all - scheduler-driven or not - so R_i and R_cohort approach 1 by geometry alone, and a population observed only briefly could be confirmed as a coordinated herd.

That is exactly what the antirea-range smoke run produced on 2026-11-09: 12 legitimate readers, observed over a 40 s window, confirmed at R_cohort 1.0000.

## Part 3 - The gate

Confirmation now additionally requires the member's observed event span to cover at least one full grid period: `lastSeen - firstSeen >= periodSec` (900 s at the default). Only span-eligible members count toward confirmation, and only eligible members can be named.

- Descriptive statistics are unchanged: `memberCount` and `cohortR` are still computed over all scored members, so dashboards keep the raw geometry in view.
- The result carries the new field `spanEligibleMembers` next to `memberCount`, so a host can see when a cohort is being held back by the gate rather than by the statistics.
- The activity-phase signal inherits the same gate and the same field from the shared core; it has no separate rule.
- Lab cells are unaffected: their spans cover many periods, and the suite re-verified with zero pre-existing expectations changed. What the gate refuses is not a pattern of behaviour - it refuses to confirm on evidence that is too short to mean anything.

## Part 4 - Regression coverage and the release gate

`tests/phase-span-gate.test.cjs` pins five cells:

- (a) short-span legitimate population - not confirmed (the range case);
- (b) long-span jittered legitimate population - not confirmed, as before;
- (c) long-span aligned herd - still confirmed (positive control: the gate does not blunt the real signal);
- (d) mixed spans - only the span-eligible members count and are named;
- (e) the herd-phase core itself carries the gate, not only the activity wrapper.

The fix also passed the mandatory range release gate (`antirea-range/gate.cjs`: SDK suite + frozen false-positive and detection cells + live range smoke), 6/6 PASS.
