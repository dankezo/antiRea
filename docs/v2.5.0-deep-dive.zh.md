# v2.5.0 深入解析

v2.5.0 版本的完整技术说明。主 README 保留简短的通俗摘要；以下为详细版本，完整保留。

## v2.5.0 新功能：覆盖完整的群体分组、Canary-Echo ID 与分层执行

2.5.0 版本把一夜对抗性审查得出的 SDK 合同设计产品化（完整综合见研究笔记）：证据原语、一个序贯证据引擎、一个带共享 campaign 上限的精确披露账本，以及存储绑定的游标--全部遵循一条规则：**没有事务，就没有执行；仅凭推断证据，绝不施加硬性后果--但摩擦默认开启。** 它把后果定位到产生证据的成员身上，教会证据引擎在它曾盲视的两种形态上形成群体，并附带本节末尾所述的离线校准拟合工具。它还弥补了早期经典轮次测出的分组差距--群体标记不再止步于触发时在场的成员--用基于领导者的设计取代成对分组以超越其规模限制，并附带 canary-echo id：一个带签名的表面引用，把轮换身份关联回它轮换前的身份。

- **覆盖完整的群体分组（2.5.0）：** 群体检测器的覆盖互补关联现在基于领导者--一个身份的覆盖组会与其它组的聚合位图和引用计数映射比较，没有每对状态（成对设计在实验室基准中处理 1,000 个身份的流需要 131 s；领导者设计需要 1.6 s，并能在 2.7 s 内把一个 500 身份的互补群体合并成一个组）。被标记的群体还会重新宣告自己：当一个迟到的加入者，或一个在标记触发时低于重要性下限的成员，跨过该下限（默认 25 条唯一记录）时，会触发一个补充标记--每组每 5 s 最多合并为一个--因此后果能覆盖整个群体，而不只是其最早的成员。在 v2.5.0 经典轮次中实测：切片群体的被标记/受后果集合从第 1 阶段身份的 8/18（2.4.0）变为 **18/18**，ID 遍历的第 1 阶段被守在每个遍历者恰好 500 条记录的软性下限。
- **Canary-echo id（2.5.0）：** `mintEchoId()` 发出一个带签名的合成引用 id，专为一个身份铸造（HMAC 完整性，每次铸造一个 128 位随机 nonce--不可伪造，不可批量猜测），通过 `mintEchoRecord()` 或 `canaryEchoLink()` 嵌入该身份自己的表面。当一个*不同*的身份把该 id 呈现回来时，主机用 `resolveEchoFrom()` 解析它，并把来源作为 `echoFrom` 喂入 tripwire--两个身份当场合并为一个群体，因此轮换不再重置证据时钟。在 v2.5.0 经典轮次中实测：一个触碰了来源 echo id 的轮换身份在触碰时即被合并（自身提供 0 条记录），联合群体约 1 s 后在 1,392 条并集记录处越界，两个成员都被 enroll 到 step-up。一次 echo 触碰是相关性信号，其本身绝不是恶意的证明--见 [Limitations](docs/LIMITATIONS.md)。
- **事务性披露账本：** `createDisclosureLedger()` 通过 `reserveDisclosure()`--唯一的原子执行点--对整个群体执行一个*共享*上限（已关联身份从一个精确的已提供记录并集中取用，无论它们如何轮换）。存储合同对自身强度很诚实：实现 `transactLedger()` 的存储（对 `ledgerVersion` 做 CAS，在一个事务中覆盖并集位图、预留、上限、桶和证据）获得 `mode: "enforce"`；只有 get/put 的存储获得 `mode: "audit_only"`，决定带有 `enforced: false`--SDK 绝不宣称一个有竞态的存储守不住的上限。预留是有界的（60s TTL，默认每个主体最多 2 个未完成预留和 500 条预留记录，可选的群体上限，以及为慢速导出提供的单独的主机授权长预留路径），已声明的群体注册表对未注册主体失败关闭，因为实验室测出部分注册表会悄悄把 campaign 防护降级为按成员保护。一项附带的一致性测试证明，对慢速异步存储的并行预留永远不会共同超支上限。
- **序贯证据（CUSUM tripwire）：** `createCusumTripwire()` 把四个流--谓词邻接、精确集不交铺满、冷 ID 未命中、游标速度--融合为每个群体一个单侧混合 GLR-CUSUM 累加器（零下限，边界 `ln(1/alpha)`），取代攻击者可以各自坐在 85% 之下的独立固定阈值。铺满排除了已由邻接谓词解释的记录，因此相关流不会被重复计数。**诚实的默认值：** 附带的 `r6-calib-1` 表是在脚本化实验室轨迹上拟合的（N_eff = 189），并标注为 `uncalibrated: true`，附有通知 "uncalibrated - audit only"；引擎默认为 `enforce` 模式，但只在 step-up 层级--一次符合条件的越界会 enroll step-up 摩擦和群体节奏控制，在这些表上无法启用更硬的东西。因为这些表未校准，默认值宣称的是对强脚本化证据的摩擦，绝不宣称检测率；`mode: "observe"` 仍可用于只做遥测的部署。越界在任何规模下都是遥测，但后果需要绝对规模：默认低于 150 条精确并集记录的后果下限（铺满流的评估门控常数，可通过 `consequences.minUnionRecords` 由主机配置）时，一次越界不会把任何人 enroll 到 step-up，也不会控制任何节奏--快照将其标记为 `consequenceEligible: false`。
- **分层规则，写进代码：** `clampEnforcement()` 把从行为*推断*出的群体限制在**摩擦层级**：step-up 加上软性预算下调，可以降低成员的预算，但绝不低于 500 条不同记录（`SOFT_BUDGET_FLOOR_RECORDS`--源自账本的每主体预留上限；`softBudgetStepDown()` 会把削减到零的需求恰好落在该下限）。摩擦是默认值：`defaultHerdBandResponse()` 把两个群体带都映射到它，用于推断群体，CUSUM tripwire 以 `enforce` 模式出厂。硬性上限需要主机声明的群体，或顶层校准清单（`evaluateCalibrationManifest()`--模型版本、样本量、留出 FP/FN、方法、证明者、过期时间；没有布尔型的 "calibrated" 标志）。群体检测器的 `graduated_only` 带在构造上价格为零，`validateHerdResponseConfig()` 会拒绝给它附加价格的配置--曾给该带定价的实验室原型（在覆盖上叠加冷获取乘数）把一个模拟合规团队硬切到其合法工作的 46%，而那个接线错误现在是一个启动错误，而不是一次无声的削减。
- **受保护群体：** 实测的误报形态--一个小团队系统性地审查一个完整分段--在实践中很少见，而且在真实组织中是一种*已声明*的活动（审计有计划，渗透测试在交战规则下运行）。因此，与其为所有人削弱检测，不如声明它们：`createProtectedCohortRegistry()` 记录合规/审计/支持/渗透测试主体（带原因和可选过期时间），受保护主体积累完整遥测，同时从推断证据中受到**零**后果--没有 step-up，没有预算下调，没有节奏控制。保护从不覆盖主机自身授权的后果，也不覆盖直接的每主体证据（受保护主体自己命中诱饵仍会污染它）。
- **游标 V2：** `mintCursorV2()` / `verifyCursorV2()` 把分页绑定到服务器端权威：载荷只携带位置、主体/群体/范围绑定、链序列和 `ledgerVersion`--绝不携带 LLR 或证据状态--并且在任何冲突时**存储获胜**：过期或未来的版本以及序列不匹配都会被拒绝，绝不会被悄悄升级。V1 游标保持不变。
- **归属和审查者钩子：** `createEvidenceAttributor()` 只把证据归于行动主体；跨主体贡献需要主机声明的关系，且有上限并会衰减，推断关联只用于观察，未知关联被隔离到审计。`createReviewerChannel()` 是防御者智能体想法被削减到其安全切片的版本：主机端的审查者（廉价模型、规则、人工队列）接收有界的聚合包，可以从固定词汇中返回经模式验证的*建议性*提案--它没有预算，没有拒绝权，其输出永远不能流回证据流（那会把相同的观察计数两次；一项测试对一个实时 tripwire 证明了这种单向性）。
- **后果定位（2.5.0）：** 摩擦落在产生证据的成员身上，而不是站在被标记群体中的每个人身上。`consequenceTargets()` 把 CUSUM 快照划分为摩擦目标（净贡献 > 0，未受保护）、受保护成员和非贡献成员；群体标记带有每个成员的 `memberCoverage` / `memberUniqueCoverage`，`herdFrictionTargets()` 只定位唯一覆盖具有重要性的成员（默认 25+ 条记录）。合法的 campaign 上限刻意不同：它限制群体在所有服务中的总提取量--是一个数据上限，不是对每个主体的惩罚。在 v2.5.0 经典轮次中实测：站在被标记群体中的礼貌用户和一个 5 用户 NAT 群体受到零摩擦，包括在一个专门的单元中，礼貌用户在标记过程中一直在会话中继续浏览。
- **群体形成 + 校准工具（2.5.0）：** tripwire 现在能在它曾盲视的两种形态上形成群体--已提供集合互补性关联过滤列表切片者（文本过滤器没有诚实的范围谓词，但精确的已提供集合总是已知的），以及冷遍历互补性关联其冷获取铺满不交、范围密集的 ID 区间的详情通道遍历者（热获取不贡献任何东西；单独的遍历者仍然永远不会形成群体）。决定会暴露每个流的 `bins` 供校准工具使用，`scripts/fit-cusum-calibration.cjs` 离线拟合可选的 LLR 表（在标注的实验室人设上做留一家族法）：附带的 `r7-labfit-1` 表相比 `r6-calib-1` 减少了留出误越界，但在两侧都无法胜过它，因此默认值仍为 r6，r7 的样本清单（证明者：lab-simulated）只评估到 step_down 层级。
