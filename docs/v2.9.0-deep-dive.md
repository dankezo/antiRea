# antiRea v2.9.0 - deep dive

> A minor release built from the outside in: a harvest of 51 sourced real-world data-leak cases, mapped against the SDK, found the largest true gap at the field level. Everything below is the case record, the lab record and the suite record - the corpora are seeded synthetic data, and no number here is a real-traffic measurement.

## Part 1 - What shipped

One new module, `createSurfaceGuard`, and one documented pattern, the declared-cohort union budget (`examples/declared-cohort-budget`). Everything is additive; no existing module changes behavior. Suite: 830 tests (828 pass, 0 fail, 2 pre-existing RSA-PSS skips), up from 817 in 2.8.1 - 13 new tests, zero pre-existing expectations changed. The release passed the mandatory range gate 6/6 (SDK suite, frozen FP/detection cells, live range smoke).

## Part 2 - The problem: the payload itself

The 2026-11-13 harvest collected 51 sourced incidents in 12 root-cause classes. Three classes were already this SDK's home turf (search/list enumeration, export scope, legitimate-API scraping). The class with no coverage at all was the simplest one: **a response carrying fields the route never meant to publish**. Spoutible's profile API returned the bcrypt password hash, the 2FA secret and the password-reset code for any username. The eHUST student-search endpoint returned password hashes, national id numbers, insurance numbers and bank accounts as part of a search result. Microsoft Power Apps' default OData sharing exposed 38 million records the same way. No budget catches this: the leak is not how much an identity takes, it is WHAT one ordinary response contains. The mirror failure is inbound - mass assignment, where a write handler binds `role`, `is_superuser` or `owner_id` because the caller submitted them (GitHub 2012, Rocket.Chat, Langflow).

## Part 3 - The mechanism: two layers, both directions

`createSurfaceGuard` inspects JSON-shaped payloads before they cross the boundary:

- **Denylist layer (no configuration):** field names are normalized (lowercased, `_`/`-`/spaces removed - `password_hash`, `passwordHash` and `Password-Hash` are the same field) and matched against built-in sensitive patterns for responses (credential material, secrets, tokens, national ids, bank/insurance numbers) and privileged patterns for requests (roles, admin flags, ownership ids). This layer alone is what catches an over-broad response on a route nobody declared.
- **Schema layer (host-declared):** a per-route allowlist of field names. Anything outside it is an `undeclared` violation. A field the host DID declare is exempt from the denylist layer - declaration is the host's deliberate act (a login response legitimately returns a token).
- **Consequences follow the tiering law:** default mode is `advisory` - violations are reported through `onViolation` and the payload is never touched. `strip` returns a sanitized deep copy; `block` marks the result not-ok. The guard never escalates its own mode.
- **Bounded cost:** traversal is iterative with a node cap (default 10,000); past it, the result carries `truncated: true` instead of scanning a hostile payload forever.

## Part 4 - The measurement (pre-registered gates SG-G1..SG-G6, seeds 20297xxx)

- SG-G1: an eHUST-shaped fixture flags password, password2, idNumber, insuranceNumber and bankAccount exactly, all as `sensitive`.
- SG-G2: 2,000 schema-conformant legitimate responses - **0 false positives**.
- SG-G3: 500 over-broad responses with 1,194 injected sensitive fields drawn from real case field lists, inspected with NO schema (denylist only) - **1,194 / 1,194 caught**.
- SG-G4: 2,000 legitimate requests - **0 false positives**; 500 writes with 918 injected privileged fields - **918 / 918 caught**.
- SG-G5: a hostile 100,000-field payload is capped (`truncated`), median 36 ms on the lab VM.
- SG-G6: full suite plus the range release gate, 6/6 PASS.

Recorded honestly: the first SG-G2 run reported 1,003 false positives - the fault was in the lab's own corpus generator, which emitted nested fields the declared schemas did not contain; the guard was right. The generator was fixed to match its schemas and the gates re-ran unchanged.

## Part 5 - The declared-cohort pattern

The second half of the release is documentation, deliberately. The live REA 6.9.0 test on this project's range (2026-11-12) showed a 4-identity herd draining a 500-record dataset in about 15 seconds while every herd signal stayed silent - per-identity budgets dilute under rotation. Step B of the response built a permanent reference population on the range and proved the cohort event floor, not missing reference data, is what keeps small bursts unscored; step A prototyped the lawful hard answer: **one `createRecordBudget` keyed by a host-declared cohort id**, so the cohort's distinct-record union is capped exactly. Measured over real HTTP: the declared herd stopped at exactly 150 of 500 (7 cohort refusals, 0 per-identity refusals), the identical undeclared herd took 500 of 500, and a declared cohort of one was never refused before its own 150.

It ships as a pattern, not an API, for two reasons: a wrapper would add no capability over the shipped primitive - only a second name to maintain - and the bundled store is single-process, so a named export would invite scaled hosts to mistake the pattern for the production ceiling (that path already ships as the disclosure ledger's `reserveDisclosure` and the tripwire's declared campaign ceiling). What hosts were missing was the wiring knowledge, and that is what `examples/declared-cohort-budget` provides: README, copy-and-adapt wiring, and a standalone verification of the three numbers.

## Part 6 - Stated limits

- The guard reads field NAMES, not values or ownership. A declared field filled with another user's data passes - BOLA stays the host's authorization logic, exactly as LIMITATIONS has always said.
- A sensitive value hidden under an innocuous undeclared name escapes the denylist layer; the schema layer still catches it on declared routes.
- The denylists are calibrated on synthetic corpora and real case field lists, not on any host's production traffic; unusual-but-legitimate vocabularies (a finance API returning `balance`) are handled by declaring the schema.
- The union-budget pattern is declaration-gated by design: a rotation the host never declares keeps only its per-identity budgets, and a legitimate team declared into one cohort shares its ceiling - that false positive is created by the host's own declaration and is documented, not hidden.
