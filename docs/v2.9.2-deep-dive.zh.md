# antiRea v2.9.2 - 深入解析

> 本审计版本同时修复新旧模块。核心产物是可重现的缺陷、兼容性变化和被拒绝方案记录。本地审计运行于 Windows x64，带种子的群体仍是合成数据。最终测试数、运行时与重复性能样本见 [audit-2.9.2.json](audit-2.9.2.json)。

## 第 1 部分 - 改变了什么

Ownership 明确处理乱序访问和状态上限。D2、seat occupancy 与 room guard 限制开放会话、保留活动，并报告饱和。Hold-type 标记异常会话而不泄露非有限特征。Assertion 精确比较所有被接受的字符串。Declaration 导入验证封装格式与限制。Volume、EMP 拒绝异常数值。旧 surface guard 与 e-value 路径也修复资源和恶意输入问题。

没有加入新的研究检测器。D2 与 RECOMB-03 都先写登记再做新测量，两项修改方案均未通过审计门限。保留零运行时依赖与宿主控制响应的产品边界。

## 第 2 部分 - 普通示例没有暴露的缺陷

基线把不同的孤立 Unicode 代理项 token 编码成相同替换字节，错误接受它们。未转义的 session 可改变继续 URL 的 query 或 fragment。Volume 的 `__proto__` 身份改变输出原型，而不是成为自身属性。EMP 接受负值或大于一的概率，允许无意义曲线和求和溢出。

更严重的是，全部会话开放时 `maxSessions` 不是硬上限：probe 设置为二却保留十项。只淘汰已关闭会话不能阻止持续生成身份；first-seen 注册表和活动历史也需要有界生命周期。Room guard 对较大 epoch 时间增加小数 tick 时，浮点数可能不再前进，导致循环停滞。

Surface 需要处理循环对象、稀疏数组、accessor 与原型形状键。E-value 的资源拒绝必须是原子的：悄悄淘汰或重启活动过程会改变其统计意义。

## 第 3 部分 - 修复与兼容性代价

- **Ownership：** 限制身份数、每身份事件和全实例事件；窗口计算考虑顺序；数据无法完整接纳时暴露 truncation，不再承诺完整证据。未知所有者仍只计分母。
- **D2、seat occupancy 与 room guard：** 硬接纳上限保留已有开放会话，使用有界充分活动摘要，清理身份元数据，并安全饱和计数器。`saturated` 暴露不完整遥测，抑制由缺失历史推导的正面标记。未来创建时间不计作新账户。安全 tick 构造避免不前进循环。
- **Hold-type：** 格式错误或不足的会话返回有限中性数值、`valid: false` 与原因。宿主使用分数作为证据前必须检查 validity。
- **402 与 declaration：** 在长度限制内精确比较 UTF-16 code unit，正确编码 URL 中的 session。拒绝异常选项、不支持的导入封装和过大 payload。日志满额时 append 原子拒绝，不删除旧项制造完整历史假象。
- **Volume 与 EMP：** 验证身份、分数、rarity，原型形状身份仍为自身键。Volume 每批最多 100,000 格；EMP 要求 [0, 1] 内有限概率，最多 10,000 网格点、100,000 总样本；helper 同样限样本。有效冻结阈值与同分顺序不变。
- **旧控制：** Surface 使用有界迭代遍历并明确报告 truncated；配置的 strip/block 不在扫描不完整时声称成功，默认仍为 advisory。E-value 的 step、merge 在改变状态前拒绝超容量或不安全数值增长，保留活动过程历史。

这些变化收紧异常、过大或观测不完整输入的合同。拒绝记录遥测不授权新的应用处罚。公开诊断和接受限制见 [LIMITATIONS](LIMITATIONS.md) 与[证据摘要](evidence/audit-2.9.2-summary.md)。

## 第 4 部分 - 为什么拒绝看似更好的方案

D2 候选尝试用另一种 occupancy 判别式降低 lurker 敏感度。预登记独立实验每格使用 512 个种子。Lurker 标记由 53/512 降到 3/512，但少数占座格检测从 512/512 降到 0/512，也未满足零新增 FP 的门限。决定是 DO-NOT-SHIP，不能只展示较低 lurker 数字。FAST、DRIP 默认值保留；原房间生成器缺失，原种子仍无法重放。

RECOMB-03 重新从独立成对实验判断，没有伪装验证缺失的 C181 lineage 文件。五次预登记 replicate 各评分 30,000 合法身份与 250 scraper。旧、新两对都检测了全部 1,250 scraper，经验阈值降低总体 FP。但经验对在 review-team 上的 FP 仍为 seasonal 16.32%-63.92%、overdispersed 45.84%-85.77%。所有 replicate 都失败于新增逐 persona 门限；其中一次总体 overdispersed FP 达 11.49%，也超过 10%。因此 RECOMB-03 继续排除，总体收益不足以解决高用量合法用户的损害。

研究袋审查没有发现由完整新门限支持的额外功能。历史 PASS、VOID 的 header 实验，或办公室群体同样拥有的 JA4 corroboration，都不足以扩大运行时 API。

## 第 5 部分 - 用证据与重复样本说话

测试加入带种子模型对照、异常事件序列、精确 token mutation 和输入排列。手工 mutant 单独编译，只在隔离 worker 中注入，并设未变异 control。Volume/EMP 的 70 个有意 mutant 全部被杀死；完整目录和覆盖限制见[审计记录](audit-2.9.2.json)。

房间修复与旧源码逐模块比较 80 个种子：seat occupancy 和 room guard 各 2,480 次 evaluate 在未饱和历史上保持一致，仅新增 saturation 诊断。独立 hostile probe 检查接纳与 tick 缺陷。运行时、包、range、浏览器结果与发布状态分开记录。

性能使用重复原始样本和机器元数据。[audit-2.9.2.json](audit-2.9.2.json)提供 median 和方法；旧 ownership 约 290 ms、surface 36 ms 不作为这台机器的新测量。浏览器 demo 检查是 Playwright 功能测试，不是 REA 攻击成功率或生产 bot 检测证据。

## 第 6 部分 - 仍未证明什么

Bundle 缺少部分历史生成器。原 D2 种子 parity、完整 RECOMB-10 与 EMP 群体再生，以及原 RECOMB-03 lineage 门限均明确为 NOT VERIFIED。独立 fixture 验证限定机制，不能替代缺失群体。

声明清单区分重跑结果、历史断言及 CSS、版本等非测量数字。静态资源清单覆盖每个源码文件，但不证明任意宿主 callback 下所有分配都受限。不能从合成格推断生产 FP。哈希链要证明完整性仍需外部锚定；建议性信号仍依赖宿主授权和响应政策。

本版本因此有独立解析，而非只在 2.9.1 结尾加一句：修改涉及输入合同、资源行为与旧控制，而两项校准候选是测量后拒绝，不是悄悄发布。
