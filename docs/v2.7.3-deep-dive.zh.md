# antiRea v2.7.3 -- 深入解析

*直播间版本。一个新的咨询信号发布；一个设计好的模块没有发布，本文开篇就把这两个事实都摆出来。*

## 第 1 部分 -- 发布了什么，没发布什么

**已发布：** `createHerdPhaseSignal`，一个可选启用的咨询检测器，用于检出由同一个调度器驱动的舰队，移植自研究候选 H7-01，经过两次独立的实验室验证（第 3-4 部分）--此外，在同一版本第二波中，还有五个咨询模块，每个对应一个已注册的直播间候选，且每个都只在通过自己冻结的实验室 pin 之后才构建（第 6 部分）：`createSeatOccupancySignal`、`createActivityPhaseSignal`、`createVoteBrigadingSignal`、`createRoomHopSignal`、`createReconnectStormSignal`。默认路径没有任何变化：没有任何现有模块导入它们中的任何一个，全部既有测试套件未经修改地通过。

**未发布：** `createRoomGuard`，一个房间压力模块（加入速度与房间自身基线的对比、新账户浓度、加入后的不活跃、churn），为本版设计，在自己预注册的实验室门槛上被淘汰。它的组合抓住了洪水、滴漏和 churn 单元，在四个合法单元上保持零误报--但完全漏掉了座位占用单元（第 4 部分）。按项目的一贯规则--看到数字之后不放宽门槛，不硬塞候选--它被排除，而不是半盲地发布。2.7.3 中**没有** `createRoomGuard`；任何声称相反的文档或智能体都是错的。它缺失的占用腿被重新注册为自己的候选（CAND-273-1/2），通过了自己冻结的 pin，作为独立的座位占用信号发布（第 6 部分）--组合守卫本身仍未构建。

**同时发布：** 一份面向智能体的集成指南 [`docs/AGENT-GUIDE.md`](AGENT-GUIDE.md)--从症状到模块的决策树、可复制的接线代码、安全默认值、"绝不"清单和验证清单，写给越来越多地为小型 host 完成接线工作的 AI 编程智能体。（该指南为英文版。）

## 第 2 部分 -- 案例

本版的动机来自一个直播间平台（一起看影院 + 卡拉OK 房，30 个座位的房间，公开品牌 "wetube ciné"，站点 choigivui.com），其运营者报告房间被看似由机器人驱动的 DDoS 打崩。该平台自己的 24 小时在线图表显示，整个在线人群在 03:00-07:00 前后反复成簇地掉到零--这是实时应用服务器在负载下死掉又重启的特征，而不是纯网络洪水的特征（ volumetric 攻击不会礼貌地按节奏重启你的应用）。诚实的分层，写在案例文件中，也写在本版每一份面向用户的文本里：**antiRea 守的是房间门（应用层：假用户的加入、占用、循环）；网络门属于 antiRea 不提供的 CDN/防火墙层。**案例分析：研究树中的 `CASE-LIVEROOM-WETUBE-2026-11-06.md`。

## 第 3 部分 -- H7-01 的记录（为什么 herd-phase 有资格）

H7-01（Kuramoto 相位锁定）来自一次跨学科采集。它的第 0 步探针给出了本设计的核心警告：按身份的相位锁定（R_i）能把成员共用同一网格偏移的 herd 与普通用户区分开，其干净程度与把成员各自使用*不同*偏移的 herd 区分开**完全一样**--R_i 测的是网格锁定，而不是共享调度。因此第 1 步注册了一个群体统计量 R_cohort（各身份平均相位的平均合成量，不加权），并在运行前冻结了规律：成员当且仅当 R_i(900 秒) >= 0.90；群体确认当且仅当成员数 >= 10 **且** R_cohort >= 0.80。在全新种子上（harness-v2 的会话开始事件）：

| 单元 | 已评分 | 成员 | R_cohort | 已确认 |
|---|---|---|---|---|
| LEGIT | 82 | 0 | 0.0662 | 否 |
| HERD-SHARED | 86 | 86 | 0.9977 | **是**（召回 1.000） |
| HERD-INDEP | 88 | 88 | 0.0794 | 否 |
| SALE（爆发） | 96 | 0 | 0.0608 | 否 |
| VALID | 86 | 0 | 0.0419 | 否 |
| NAT-GROUP-DIRECT | 85 | 0 | 0.0634 | 否 |

四个有约束力的门槛全部通过（bootstrap 分离重叠 0.0000，上限 0.50；三个空单元上的误报成员率均为 0，预算 1%）。HERD-INDEP 是为模块形态辩护的那个单元：没有群体这条腿，检测器会按设计标记 88/88 个无辜身份。

## 第 4 部分 -- roomguard pin（房间加入适配 + RoomGuard 被淘汰）

构建之前，两个规划中的模块都走了一遍全新的冻结注册（`roomguard-lab/REGISTRATION-ROOMGUARD.md`，种子家族 20286xxx，已用 grep 验证未被使用），在带种子的**房间加入**事件流上：四个合法单元--稳定的晚间观看；一次**涌入**（外部链接发布后 50 个现有用户在 2 分钟内加入）；一次**定时开场**（60 个现有用户在已宣布的放映时间的一分钟内加入--合法的相位集中，危险的空假设）；卡拉OK 黄金时段--以及六个机器人单元：瞬间洪水（10 秒内 200 个全新账户）、慢速滴漏（一小时内每分钟 1-2 个）、churn 循环、座位占用（30 个全新账户占满卡拉OK 全部座位并沉默地坐着），以及在共享与独立 900 秒网格上的重连 herd。

Herd-phase 采用 pin 的作用域规律（群体 = 评估前 24 小时内首次出现的身份），在加入流上重现了它在 H7-01 中的行为：共享网格的重连 herd **被确认**（60/60 成员，R_cohort 0.9978），独立网格的 herd **未被确认**（按 R_i 有 60 个成员，R_cohort 0.0421），任何合法单元中都没有确认、没有作用域内的已评分身份。门槛 G-FP2、G-B5、G-B6 通过--模块得以构建。

RoomGuard 压力组合通过了它的误报门槛（在合法单元的 4 × 20,161 个评估 tick 中从未达到"高"--包括 25 次加入/分钟的涌入和一分钟 60 次加入的定时开场，两者都被新颖性与不活跃两条腿压住，因为真正的涌入者是现有账户，随后会观看和聊天），并通过了四个机器人门槛中的三个（洪水在 +60 秒达到高，滴漏通过持续路径在 +31 分钟，churn 在 +30 秒）。**门槛 G-B4 彻底失败：在占用单元中，压力在七天里的任何一个 tick 都没有达到过高。**这一机制是用同一个评估器代码做的逐 tick 诊断验证的，而不是推断的：爆发路径的三条腿在不同的时间达到峰值（速度在 +60 秒触发，此时占用者还太年轻、进不了不活跃样本--不活跃比例 0.14；到 +180 秒时不活跃已成熟到 0.82，但 60 秒的加入窗口已经滑过了那次爆发），持续路径的新账户比例被黄金时段的真实加入者稀释到 0.63-0.67，永远低于冻结的 0.70 标准。占用攻击的是**占用率**，而不是加入速度；注册的信号家族里没有占用这条腿。注册规律禁止在看到数字之后再添加一条，所以 RoomGuard 没有以任何形式被构建--甚至没有作为描述性遥测，因为注册里没有预备这个退路。

## 第 5 部分 -- 已发布模块的契约

`createHerdPhaseSignal(options?)` -> `{ observe, evaluate, snapshot }`。按身份喂入一个同质的事件流（`observe({ identity, ts })`）；`evaluate({ asOfTs?, cohortWindowMs? })` 运行冻结的规律：在 900 秒网格上取相位，身份在 >= 8 个事件时被评分，成员为 R_i >= 0.90，确认需要 >= 10 个成员**且** R_cohort >= 0.80（R_cohort 取**全部**已评分身份的平均相位，不加权--实验室定义，不是只对成员求平均）。成员只在确认时被点名；未确认的结果只报告成员数量和一个空列表。每个输出都带有 `enforcement: "none"`。状态有界（身份数与每身份事件数都有上限，计数器在 snapshot 中），评估是确定的，格式错误的时间戳是结构化的空操作，该模块零运行时依赖，也不接入默认路径。

声明的限制（同样见 `docs/LIMITATIONS.md`）：900 秒是唯一被验证的调度器周期；有自己固定机器作息的合法群体（个人 cron 舰队、办公机器）不在实验室人群中，因此那里的误报率没有被测量--群体腿和点名规则是结构性的缓解，而不是测量；随机化偏移的 herd 按设计不可见；低于 8 个事件下限的身份永远不会被评分，所以一次性洪水不在范围内。所有数字都是带种子的模拟--只有内部效度，不是真实流量表现。

## 第 6 部分 -- 第二波：六个候选、六个冻结 pin、五个模块建成

占用缺口和另外五个直播间形态，先以便宜的第 0 步提案注册在 `roomguard-lab/CANDIDATES-273.md` 中（研究袋 INDEX 第 10 节）。在发布的第二波中，每个候选都在自己冻结的注册下工作--规律、门槛、误报单元和淘汰条件都写在任何 pin 数字存在之前--运行在第一波的模拟器基底加上每个候选点名的危险空单元上（`roomguard-lab/cand273-lab/`：注册、pin、`CAND273-RESULTS.md`；全新种子家族 20287xxx，已用 grep 验证未被使用；每个 pin 运行两次，逐字节相同）。六个全部通过了冻结门槛；五个模块发布（273-1 与 273-2 是同一个模块的两个配置）。

| 候选 | 冻结规律（简式） | 决定性的 pin 数字 |
|---|---|---|
| 273-1 座位占用（FAST） | 新且闲置的座位占比 >= 0.50，持续 600 秒 | 合法峰值：卡拉OK 0.0667，沉默观众 0.1333，涌入 0.0200--20,161 个 tick/单元无标记。爆发式占用在 +660 秒被标记（门槛 <= 900 秒） |
| 273-2 座位滴漏（DRIP 配置） | 同一估计量，>= 0.34，持续 3,600 秒 | 慢速滴漏在它占完最后一个座位前 5,100 秒被标记（门槛 >= 1,800 秒）。压力单元（全新用户全部沉默，注册量 3 倍）峰值 0.2333，未标记，描述性 |
| 273-3 活动相位 | 在活动时间戳上用 herd-phase 规律，群体作用域限于首次出现 <= 24 小时 | 共享聊天 herd 被确认（60 成员，R_cohort 0.9230）；偏移 herd 未被确认（0.0402）；高潮单元在作用域内和作用域外均为 0 成员。不加作用域的共享 herd 不会被确认（0.2539）--作用域是规律的一部分 |
| 273-4 投票 brigading | 60 秒窗口，s = N - 0.5T，A = max(0, A+s)，在 >= 2 个窗口上 A >= 12 时标记 | 合法 A = 0（包括替代参数人群）；涌入的大规模跳过在一个窗口内峰值 A = 9--比一个 brigading 窗口的 7.5 还大--从未被标记；brigading 在它的第三首歌之前被标记 |
| 273-5 房间跳跃 | 任意滑动一小时内 >= 16 个不同房间；在标记占比 > 25% 时自我解除 | 冲浪者最多 6/小时，重度冲浪者最多 11；测绘者在第一小时内被标记 20/20；解除从未触发 |
| 273-6 重连风暴 | 每来源 >= 40 次连接 / 600 秒 且会话中位时长 < 5 秒；在 > 25% 时自我解除 | 稳定来源最多 2，不稳定 13，通勤者 21 次连接/10 分钟；风暴在第一个窗口内被标记 20/20。分布式风暴（200 x 25）标记 0--有记录的盲点；没有注册人群门槛，因为合法的通勤爆发在人群层面能达到 417/10 分钟 |

设计血统，按项目积累知识的规则：座位占用是聚束监测器家族的人群统计量（一种房间状态，没有按身份的裁决）；投票 brigading 是 CUSUM 式的单侧积累，把 C27 的教训（慢形态靠持续积累而非速度取胜）用在窗口上；房间跳跃和重连风暴带有 C35 的自我解除模式（一个可能大规模误火或被投毒的信号会暂停自己、不点名任何人）；活动相位直接复用 H7-01 的 herd-phase 核心，而不是重复造它的数学；重连风暴的按来源核算遵循从不只按 IP 分组的一贯规则。塞队列（273-4 的一个变体）已注册但没有被测量，也不在任何地方被声称。所有数字都是带种子的模拟--只有内部效度，不是真实流量表现。

## 第 7 部分 -- 验证与覆盖

测试套件：**748 个测试（746 通过，0 失败，2 个预先存在的 RSA-PSS 跳过）**，高于 2.7.2 的 682 个--66 个新测试（12 个 herd-phase：共享网格确认、独立偏移拒绝、相反子 herd 抵消、均匀随机空假设、最小成员下限、事件下限、针对一个相反的旧 herd 的 24 小时作用域、asOf 截止、畸形事件纪律、选项验证、两个内存上限、确定性；48 个分布在第二波的五个模块上，在确定性的合成流上钉住每条冻结规律，外加验证、边界和解除用例；6 个空实例回归测试，由下面发布前基准测试的那次修复添加），没有改动任何既有预期。`npm run check`（测试 + 审计脚本）通过；`npm run benchmark:build-sdk` 通过。默认路径逐字节相同，只有 `src/index.ts` 中新增的六行导出和六个新模块文件（已通过对 `src/` 与 2.7.2 树做校验和 diff 验证），且没有任何新模块被任何现有模块导入。经典发布轮在发布前确实重跑了，作为发布前基准测试的 A 部分，与 2.7.2 基线在每个单元上一致；B 部分（一个连续模拟一整天、共 66,722 个事件的直播间集成基准）检出了占座、滴漏、加入 herd 和投票 brigading，误报为零，还抓住了一个单元套件漏掉的缺陷--在座位占用、房间跳跃和重连风暴上，对一个全新实例无参数调用 `evaluate()` 会抛异常（它们的默认 `asOfTs` 回退到了未初始化的 `latestTs`）；修复使空实例返回惰性结果，只触及那三个新模块文件，并由上面那 6 个回归测试钉住。基准测试的两个非缺陷发现（自我解除对一场集中的夜间风暴的覆盖；活动相位在繁忙聊天流上的稀释）记录在 LIMITATIONS 和智能体指南中。

测试**没有**覆盖什么：任何种类的真实直播间流量；900 秒以外的调度器周期；随机化偏移的 herd（按设计不可见）；合法的机器作息子人群；塞队列（已注册，未测量）；来自养老账户的 brigading 或占座（新颖性是这些信号的主要腿）；分布式的低速率重连风暴（有记录的盲点，第 6 部分）；网络层攻击（按分层在范围之外）。农场校准门槛（约 11 月 16 日）仍是整个咨询层预定的第一次真实流量检验。
