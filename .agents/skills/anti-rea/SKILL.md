# antiRea — evidence-led web hardening skill

Read `docs/LIMITATIONS.md`, `docs/THREAT_MODEL_REA.md` and `docs/SERVER_SIDE_CONTROLS.md` first. This skill does NOT make sites unclonable or block `morluto/rea`.

## Stage 1 — scope and consent

1. Confirm target project is owned/authorized by user; inspect framework, built assets, API routes, authn/authz and threat surface.
2. Classify sensitive assets: server secrets, customer data, private formulas, third-party data and content rights.
3. List what an authenticated user can legitimately see; assume it can be copied or screenshotted.

## Stage 2 — highest-value repairs (P0)

1. Move proprietary logic, prompts and secrets into server-only modules.
2. Test object-level and field-level authorization server-side, not only hidden UI elements.
3. Add rate limits/quotas (`createQuotaGuard`), export caps, pagination limits (`maxPageSize`, `maxPage`), minimal response fields and access logs.
4. Protect source maps/production artifacts without interfering with developer or accessibility tools.

## Stage 3 — optional instrumentation, informed by risk

- Tier 1: disable public production source maps in framework config; optional `injectAgentNotice`, `signSvgPath` fragile provenance markers. Explain weak evidence value.
- Tier 2: `createQuotaGuard` for per-account/API-key/IP rate limits and pagination caps; `createRecordBudget` for the coverage dimension quotas cannot express - a per-identity ceiling on DISTINCT records received per window, with `createExportGuard` rejecting dataset-scale exports before the handler runs and charging allowed exports against the budget at a multiplier, and `mintCursor`/`verifyCursor` for session-chained pagination that rejects skip-ahead, cross-session and stale replay; `createWebBotAuthVerifier` for RFC 9421 Web Bot Auth signature verification (a verified signature identifies a key holder for the covered request; it is not authorization and never a reason to skip quota or authz checks); `handleCanaryTrapRequest` (with `normalizeCanaryPath`) on deliberately unused server routes with trusted-session resolver; alert for investigation, do not auto-ban. `createCanaryMaze` (opt-in, disabled by default) serves a deterministic link maze under a robots-Disallow prefix with hard per-IP and daily caps; hits alert for investigation only - it taxes and detects bulk link-followers and never stops a client that calls real endpoints directly. `createDecoyMirage` (opt-in) answers the same unused routes with deterministic synthetic documents instead of 404, under its strict safety subset (unused routes only, inert content, never mixed into real responses). `createFlowScorer` is log-only workflow-sequence telemetry (boundary probes, post-429 persistence, coverage streaks, export bursts, canary/decoy contact) with a verified-bot `isExempt` lane; it never blocks, and its opt-in `onTaint` callback is the only sanctioned bridge from scoring to enforcement - the host may tighten a tainted identity's record budget via `setOverride`. `createHerdDetector` correlates ACROSS identities (signup chaining per IP plus coverage-complement linking) to catch sybil herds that dilute per-identity budgets by rotation; since 2.5.0 the complement linking is leader-based (an identity's coverage group is compared against other groups' aggregate bitmaps/sets, no per-pair state) and a flagged group RE-ANNOUNCES itself with a supplementary flag when a late joiner or a pending partial contributor crosses the materiality floor (1/12 of the flag floor), so a flag snapshot is no longer limited to whoever was present and material at first crossing; it flags groups via `onFlag` with a response band, and `applyHerdLadder` lowers flagged members' budgets only for the high-tiling herd partition profile - low-tiling flags (the legitimate systematic-review profile) are refused in code and route to graduated response instead. Canary-echo ids (`mintEchoId` / `verifyEchoId` / `resolveEchoFrom`, plus the `mintEchoRecord` and `canaryEchoLink` embedding helpers) are signed synthetic reference ids minted FOR one identity: when a different identity presents one back, the host feeds `resolveEchoFrom`'s result into the CUSUM tripwire as `CusumEvent.echoFrom` and the two identities merge into one cohort - unforgeable without the server secret, unguessable in bulk (random nonce per mint), and inert for a client that only uses its own surface. Every record-serving surface, including server-rendered HTML, must feed it events and consume budget, or it is a silent bypass of both layers. `detectAutomationSignals` (legacy alias `initCdpGuard`) optional low-confidence telemetry only.
- Tier 2 (v2.5.0 evidence & enforcement layer): `createDisclosureLedger` meters a cohort-wide shared ceiling over the exact served-record union through the single atomic point `reserveDisclosure` - enforcement exists only over a `transactLedger` CAS store; get/put stores run in a declared `audit_only` mode (`enforced: false`), reservations are bounded (TTL, per-subject caps, host-authorized long path), and declared registries fail closed for unregistered subjects (partial registries silently degrade campaign guards). `createCusumTripwire` fuses adjacency/tiling/cold/velocity streams into a one-sided mixture GLR-CUSUM accumulator per cohort (zero floor, B = ln(1/alpha)); its bundled `r6-calib-1` tables are fitted on scripted traces and ship labeled uncalibrated/audit-only, and the default mode is `enforce` - but only at the step-up tier, since nothing harder may engage on uncalibrated tables by default. Crossings are telemetry at any scale but carry consequences (step-up enrollment, cohort pacing) only once the cohort's exact union coverage reaches the consequence floor - 150 distinct records by default, the tiling gate constant, host-configurable via `consequences.minUnionRecords`; snapshots expose `consequenceEligible`, `contributingMembers` and `protectedMembers`, and hosts enrolling from `onCampaignFlag` must check eligibility first (the v24 classic-test polite+NAT fix). Consequences are tiered by law (`clampEnforcement`, 09:44 revision): behavior-inferred cohorts cap at the friction tier - tripwire-gated step-up plus a soft budget step-down bounded below by the 500-record floor (`softBudgetStepDown`; `defaultHerdBandResponse` ships that friction as the default response to both herd bands) - hard ceilings need a host-declared cohort or a ceiling-tier `evaluateCalibrationManifest`, cold pricing and below-floor cuts are refused in code for inferred cohorts even when configured, and the herd `graduated_only` band carries zero price (`validateHerdResponseConfig` rejects priced configs - the R5 compliance lesson). Host-declared protected subjects (`createProtectedCohortRegistry` - compliance/audit/support/agreed-pentest declarations with reason and optional expiry) accrue full telemetry but receive zero inferred-evidence consequences; protection never covers host-authorized consequences or direct per-subject evidence. `mintCursorV2`/`verifyCursorV2` bind pagination to store authority (payload = position + binding + sequence + ledgerVersion, never evidence; store wins on any conflict). `createEvidenceAttributor` credits the acting subject only (declared cross-links capped + decayed, inferred observation-only, unknown quarantined). `createReviewerChannel` is the only LLM-shaped surface: bounded aggregate bundles out, schema-validated advisory proposals back, architecturally one-way - reviewer output never feeds the evidence stream. 2.5.0 additions: friction consequences are targeted by contribution - `consequenceTargets()` partitions a CUSUM snapshot (net contributors minus protected) and `herdFrictionTargets()` keeps only herd members with material unique coverage (`HerdFlagSnapshot.memberCoverage` / `memberUniqueCoverage`; floor `HERD_FRICTION_MIN_UNIQUE_RECORDS` = 25), so bystanders inside a flagged group get zero friction; a lawful campaign ceiling is not targeted this way (it caps the cohort's total over ALL serves - a data cap, not a punishment). The tripwire's `formation` options form cohorts on the two formerly blind shapes - served-set complementarity for filtered lists and cold-walk complementarity (disjoint, range-dense cold fetches; warm fetches never contribute) for the detail channel - and decisions expose per-stream `bins` for calibration tooling. `scripts/fit-cusum-calibration.cjs` fits opt-in LLR tables offline (LOAFO over labeled lab personas); the shipped `r7-labfit-1` set is opt-in only (its sample manifest, attested lab-simulated, reaches the step_down tier) because it did not beat `r6-calib-1` on both holdout sides - the SDK default stays r6.
- Tier 2 (v2.6.0 feature-abuse layer): when the host's risk is abuse of a FEATURE at herd scale - many cheap identities using an expensive action correctly, each inside its own limits, jointly draining compute, a promo/trial pool or fairness on one endpoint - meter the operation itself, not just the records it returns. Have the host declare action prices (`createActionBudget`: abstract cost units per action type, host-declared, never invented by the SDK) and enforce them through reserve/commit on the same `transactLedger` CAS store contract as the disclosure ledger; a get/put-only store runs `audit_only` (`enforced: false`) and promises only the honesty of the ledger, never blocking under concurrency. Register canary actions (`createCanaryActionRegistry`): target keys no legitimate UI ever emits, whose touch is direct per-subject evidence that taints only the toucher and links it into flagged groups via `taintedMembers`. Declare the host's legitimate teams (compliance, support, QA, partner integrations) into the protected registry up front, so inferred-evidence friction never lands on them. Feed every priced action to `createActionCohortTracker` (complement grouping for herds splitting one job across disjoint targets, shared-target grouping for herds converging on one promo/endpoint; IP is never a grouping key) and apply consequences only through the tiering law transposed: inferred cohorts get observe + step-up + a soft step-down floored at the price of the most expensive single action (`clampActionStepDown` / `derivedSoftFloorCost`); hard locks need a host-declared cohort (ceilings arm at declaration) or a ceiling-tier manifest. Set expectations at the correct boundary before wiring any of this: under open registration with a free, unlimited feature, this layer can only tax and delay - it cannot make abuse impossible, because a patient herd is indistinguishable from a genuine flash crowd - and it says nothing about business-logic correctness (pricing math, inventory races, IDOR/authorization, injection, auth logic are host code defects a metering layer cannot detect or fix; never advertise otherwise).
- Tier 2 (v2.8.0 room guard + evidence layer): `createRoomGuard` is the combined room-pressure guard the 2.7.3 cycle excluded at its frozen squat gate, re-registered as RECOMB-06 with the seat-occupancy leg declared up front (pressure v2: burst / sustained / churn paths OR the occupancy FAST/DRIP laws, 30 s ticks, population-only output, `recommendStepUpForNewJoins` for NEW joins only - seated members never receive a consequence; hole A1, a squatter emitting 1-2 activity events, is declared open). The evidence layer pins verdict semantics: `createConfigProvenance` hashes a signal's effective configuration (canonical serialization + SHA-256, CS-02) so every evidence item can name the exact detector that produced it; `classifyWebBotAuthVerdict` / `classifyHostVerificationFact` freeze BS-01 verified-neutral semantics (verified and unverified both carry an evidence delta of exactly 0; only proven forgery - the conclusive cryptographic signature failure or an FCrDNS contradiction - is evidence, and hosts must never key enforcement on a verdict detail string themselves); `issueStepUpProof` / `createStepUpProofVerifier` implement the CAP-01 single-use Ed25519 step-up proof (bound to identity + config hash + challenge-config hash, lifetime capped at 3,600 s, nonce-consume hook required at construction and called only at the replay step); `evidentiaryRoleOf` / `auditEvidencePack` / `decorateSignalResult` implement KT-01 (CONVICTING only with its own passed gates, the BS-01 fact conditional on spoofed, corroborating-only packs mechanically ineligible for consequences, tier 3 forbidden for inferred evidence). The C27+C35 enforcement conversion is still NOT shipped: it waits on the farm gate and a production stratum-assignment mechanism.
- Tier 3: `encryptPayload`/`decryptPayload` with `createInMemoryReplayGuard` (or Redis `SET NX PX`) require CryptoKey and atomic replay store; use for independent trust boundaries and never claim a browser-held key is secret. Do not replace HTTPS.
- Tier 4: `mountForensicWatermark` with opaque server-issued rotating token; post privacy notice and define audit-ledger retention. `BehaviorShield` is opt-in telemetry, not license to degrade users.

## Stage 4 — testing and reporting

1. Run `npm run check` locally and relevant framework build tests.
2. Inspect public bundles for source-map leakage (`scripts/verify-build.py` or `node scripts/run-audit.cjs <dir>`) and test backend APIs for BOLA/field exposure and quotas.
3. If comparing to REA, use a dedicated consented browser and versioned observation protocol in `docs/BENCHMARK_PROTOCOL.md`.
4. Report verified / plausible / unsupported claims separately; explicitly list bypasses, accessibility and privacy implications.
5. Never instruct agents to sabotage other software or make unverified claims of protection.

## Validation (2.1)

For changes claiming resistance to browser-level observation, use the local twin SaaS and record both functional/collateral impact and real observation evidence. Start with `npm run check`; build browser modules with `npm run benchmark:build-sdk`. Follow `docs/DEMO_BENCHMARK_2_1.md` for Playwright and `benchmark/rea/README.md` for operator-run **real** REA captures. The Playwright results are NOT REA results. For clone-resistance claims, follow `docs/RECONSTRUCTION_STUDY.md`. Never publish security effectiveness percentages inferred from canary hits or weak automation hints.
